# Divergências conhecidas em relação ao sqlparser-rs

Registro **obrigatório** de toda diferença de comportamento entre o `Lepton.SqlParser.Core` e o sqlparser-rs da versão de `UPSTREAM.json`. Requisito do projeto: "documentar incompatibilidades conhecidas" e "evitar divergências silenciosas".

**Regras:**
- Toda divergência tem um ID (`DIV-NNN`) e, se possível, um teste que a evidencia.
- Testes portados que falham por causa de uma divergência ficam com `[Fact(Skip = "DIV-NNN: ...")]`, nunca apagados.
- Quando a divergência for resolvida, mude o status para **Resolvida** (não apague a linha) e remova o `Skip`.

| DIV-003 | Tokenizer / Unicode | Caracteres fora do BMP (pares substitutos). | DIV-004 | Tokenizer / Dialetos / Unicode | Classificação Unicode dentro do BMP. `is_alphabetic()` do Rust é a propriedade `Alphabetic` (letras + `Nl` + `Other_Alphabetic`, que inclui sinais vocálicos `Mn`/`Mc`); `char.IsLetter` só aceita `L*`. `is_alphanumeric()` acrescenta `Nd`/`Nl`/`No`; `char.IsLetterOrDigit` só `L*` + `Nd` (convencoes.md §10). | DIV-005 | Parser / Display / spans / pilha | Proteção contra estouro de pilha (feature padrão `recursive-protection` do Rust, crate `recursive`). **Igual ao Rust:** `#[recursive::recursive]` (`stacker::maybe_grow`: com menos de 128 KiB livres, o corpo roda numa pilha nova de 2 MiB) virou `StackGuard` (`Support/StackGuard.cs`; convencoes.md §13, caso 123) nos mesmos seis pontos: `Display` de `Expr` (`Expr.Fmt`), `parse_subexpr`, `parse_interval`, `parse_data_type_helper`, `parse_query` e `parse_table_factor`. `RecursionLimitExceeded` só ocorre quando o contador chega a 0: o `TryDecrease` deixou de converter falta de pilha nesse erro. Erros que sobem por muitos níveis não acumulam pilha (caso 124). **Diferente:** (1) a pilha nova é de **outra thread**: estado `[ThreadStatic]`/`ThreadLocal` de um dialeto do usuário não é visto pela continuação (a cultura e o `ExecutionContext` são levados); numa thread STA do .NET Framework, o `Join` bombeia mensagens COM; onde não há threads (WebAssembly), a troca lança `PlatformNotSupportedException` (capturável); (2) a zona vermelha é a de `RuntimeHelpers.EnsureSufficientExecutionStack`: 128 KiB (64 bits) no .NET Core/.NET 5+, como o Rust, e metade da pilha no .NET Framework 4.8; (3) **desvios a mais** (`// PORT-DEVIATION DIV-005`), em funções que o Rust não marca: `Expr.Span()`, porque estourava com ~130 termos encadeados numa thread de 1 MB; desde a F1 (revisão R4, item 2), o `Display` de `Query`, `SetExpr` e `TableFactor` (`Query.Fmt`, `SetExpr.Fmt`, `TableFactor.Fmt`) e, desde a P2, o `Span()` dos mesmos três tipos (`Query.Span()`, `SetExpr.Span()`, `TableFactor.Span()`). Antes da F1, 80 subconsultas aninhadas em `FROM` ou 200 junções entre parênteses (aceitas com `recursion_limit` elevado) estouravam uma thread de 256 KB no `ToString()`, e uma cadeia de 5.000 `UNION ALL` estourava a thread principal de 1 MB com o limite padrão; antes da P2, o `Span()` das mesmas três entradas também estourava (medido com o Core anterior, Release, net8.0: as três numa thread de 256 KB e os 5.000 `UNION ALL` também numa de 1 MB); agora as três funcionam em qualquer pilha, no `ToString()` e no `Span()` (20.000 `UNION ALL` numa thread de 256 KB); (4) os quadros do C# são muito maiores que os do Rust (Debug/Tier0: ~8 KB por nível de `Expr.Fmt`, ~12 KB por nível de parênteses), então recursões que o Rust também **não** protege estouram mais cedo: a igualdade e o `GetHashCode` gerados dos records (registrados à parte, DIV-010) e a recursão só por `parse_statement`; (5) o visitor gerado usa o mesmo padrão (o Rust marca `visit`; DIV-009) | Baixo: com o limite padrão (50), o parse, o `ToString()`/`ToSql()` e o visitor não estouram em nenhum caminho conhecido; cadeias que o contador não limita (`a + b + ...`, `x AND y AND ...`, `UNION ALL`) funcionam com 20.000 termos. | DIV-009 | Visitor / pilha | O derive marca cada `visit` com `recursive::recursive` (a pilha cresce sob demanda). O .NET não aumenta a pilha de uma thread: o visitor gerado testa `RuntimeHelpers.EnsureSufficientExecutionStack()` na entrada de cada nó e, se faltar pilha, continua a visita numa **thread nova** (2 MiB, o tamanho dos segmentos do crate `recursive`) e espera por ela; exceções voltam para a thread original. | DIV-010 | AST / igualdade / pilha | A igualdade que o compilador gera para os records da AST (`Equals`, `==`, `!=` e `GetHashCode`; também a de `Sequence<T>`, que compara item a item) é recursiva e **não** tem `StackGuard`. No Rust, o `derive(PartialEq, Eq, Hash)` também é recursivo e também fica fora do `recursive-protection`, mas os quadros do Rust são muito menores, e o estouro na prática só aparece no C#. Medido na revisão R4 (item 1): `WHERE id = 0 OR id = 1 OR ...` com 8.000 termos e depois `s == p.Parse(sql)` estoura a thread principal (1 MB) no net8.0; no net48, a partir de 6.000 termos; numa thread de 256 KB (IIS), a partir de 1.000. Um estouro de pilha encerra o processo (não dá para capturar). **Por que não corrigido:** os records são port fiel do `derive` (convencoes.md §7); escrever ou gerar `Equals`/`GetHashCode` com `StackGuard` para centenas de tipos foi rejeitado pelo integrador (F1). **Uso seguro:** comparar o SQL gerado (`a.ToSql() == b.ToSql()`, protegido pela DIV-005); se precisar da igualdade estrutural, comparar numa thread com pilha grande (`new Thread(..., 64 * 1024 * 1024)`) ou limitar antes o tamanho do SQL de terceiros; não usar nós profundos como chave de `Dictionary`/`HashSet` | Baixo: só igualdade e hash de ASTs com milhares de níveis (cadeias de operadores que o contador de recursão não limita) ou com `recursion_limit` elevado. ## Decisões do responsável

- **2026-10-14: classificação de caracteres Unicode (DIV-003 e DIV-004).** Manter a classificação do .NET (`char.IsLetter`, `char.IsLetterOrDigit`, `char.IsWhiteSpace` etc.), sem tabelas Unicode próprias para imitar o Rust.
  - **Motivo:** o impacto é marginal. Só afeta identificadores **sem aspas** com caracteres fora do BMP (emojis, letras matemáticas) ou caracteres raros do BMP (`²`, `ⅷ`, sinais vocálicos de escritas indianas). Nomes com acentos do português, identificadores entre aspas, strings e comentários se comportam igual ao Rust.
  - **Consequência para o port:** não "corrigir" essas diferenças sem nova decisão. Só reabrir se surgir um caso real de uso. A alternativa é gerar tabelas com as propriedades `Alphabetic`/`Numeric` do Unicode na versão usada pelo Rust: trabalho moderado e isolado, sem impacto no resto do código.
