## Decisões (para convencoes.md §13)

1. **`#[derive(Copy)]` em struct de dados da AST** (`WithData { data: bool, statistics: Option<bool> }`) → `public sealed record` posicional (caso 36), **não** `readonly record struct` (caso 6). Motivo: o caso 6 é para tipos pequenos que precisam de ordenação (`Location`, `Span`); na AST, `Copy` não muda nada num record imutável, e `record struct` faria `Option<WithData>` virar `Nullable<WithData>`, diferente dos demais campos opcionais. Primeiro uso: `Ast/Ddl/WithData.cs`.
2. **Constante de `enum` C# dentro de um record com propriedade homônima anulável** (`CreateTable.OnCommit` é `OnCommit?`, ou seja, `Nullable<OnCommit>`): a regra "Color Color" do C# só vale quando a propriedade tem exatamente o tipo homônimo, e `Nullable<OnCommit>` não tem. Então `OnCommit.Drop` dentro de `CreateTable` seria lido como membro da propriedade (erro). Forma adotada: qualificar `Ast.OnCommit.Drop` (extensão do caso 38). Records (tipos-referência) anuláveis não têm o problema. Primeiro uso: `Ast/Ddl/CreateTable.cs`.
3. **`match` sobre `Option<EnumCSharp>`** (`match &self.table_type { Some(AlterTableType::Iceberg) => .., None => .. }`) → `switch (TableType) { case AlterTableType.Iceberg: .. case null: .. default: throw }`. Para `enum` C#, o `default: throw` continua necessário (um `enum` pode ter valores fora da lista). Primeiro uso: `Ast/Ddl/AlterTable.cs`.
4. **`match` com braço `_ => ()`** → `default: break;` (não lança). O `default: throw` (§6, regra 3) fica só para `match` exaustivo sem curinga. Exemplos: `HiveDistributionStyle` e `HiveIOFormat` em `CreateTable.Fmt`.
5. **`format!`/`to_string()` montando pedaços de um `write!`** (`if_not_and_name` e `to` em `CreateView`; `params: Vec<String>` + `params.join(", ")` em `CreateOperator`): segui a decisão 3 da A2 (escrita direta na mesma posição da saída). Para o `join`, o primeiro item sempre existe, então cada item seguinte é escrito com o separador `", "` na frente; o texto é idêntico. Arquivos: `Ast/Ddl/CreateView.cs`, `Ast/Ddl/CreateOperator.cs`.
6. **`impl Spanned for X` que fica em `ddl.rs` (fora de `spans.rs`)** → comentário na posição do Rust: `// PORT-TODO: \`impl Spanned for X\` (ddl.rs:NNNN) entra com os spans (ast/spans.rs).` Assim quem portar os spans encontra também os `impl` espalhados nos módulos. Ver a lista em "Pendências".
7. **`impl From<X> for crate::ast::Statement` definido fora de `mod.rs`** → membros `public static Statement From(Ast.X v)` num `partial` de `Statement`, em arquivo próprio na pasta da unidade de origem (`Ast/Ddl/Statement.From.Ddl.cs`, origem `src/ast/ddl.rs`). Mesmo padrão da A4 (`Ast/Mod/Statement.From.cs`); `Statement` já é `partial` (A2).
8. **Enum com dados e sem `Display`** (`CreateCollationDefinition`) → `abstract record` com variantes aninhadas, **sem** `IDisplay` e sem `ToString()` próprio (o texto é escrito pelo `Display` do tipo que o contém, `CreateCollation`). Mesmo tratamento que as unidades vizinhas deram a `HiveDistributionStyle` e `ResetConfig`.
9. **Variáveis de padrão em `if` consecutivos**: em C#, `if (x is { } v)` declara `v` no bloco que contém o `if` (não só no `if`). Quando o Rust repete o nome (`if let Some(is_enabled) = ..` duas vezes em `CreateTable`), o C# usa nomes distintos (`isEnabled`, `changeTrackingIsEnabled`); sem isso, CS0128.
