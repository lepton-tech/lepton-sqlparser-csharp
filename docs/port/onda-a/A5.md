## Decisões (para convencoes.md §13)

1. **Alinhamento `{:>}` / `f.align()`** (só `KeyOrIndexDisplay`; usado em `ddl.rs:2067` e em `table_constraints.rs:346` e `:549`). O `Formatter` não tem alinhamento. Tradução: o corpo de `fmt` vai para `private void FmtAligned(Formatter f, bool alignRight)` (`alignRight` substitui `matches!(f.align(), Some(fmt::Alignment::Right))`); `Fmt(f)` = lacuna `{}` (`alignRight: false`); `internal void FmtAlignRight(Formatter f)` = lacuna `{:>}` (formatador novo, `alignRight: true`). Chamada: `write!(f, "UNIQUE{:>}", x)` → `f.Write($"UNIQUE"); x.FmtAlignRight(f);`. Alternativa para o integrador, se preferir algo genérico: acrescentar `Formatter.Align` e aceitar `{x:>}` no handler; aí `FmtAlignRight` some. Primeiro uso: `Ast/Ddl/KeyOrIndexDisplay.cs`, `ColumnOption.cs`.
2. **`{x:?}` de `Keyword`** (`write!(f, "ON CONFLICT {keyword:?}")`): o `Debug` derivado imprime o nome da variante, que é o nome do membro do `enum` C#: `{keyword.ToString()}`. Não usar `{keyword}`, que daria `ToSql()` (texto SQL, diferente em `END_EXEC`). Primeiro uso: `ColumnOption.cs`.
3. **Campo chamado `equals`** (CS0102: a propriedade `Equals` colide com os métodos `Equals` sintetizados pelo record): sufixo `Value` (`EqualsValue`), por analogia com o caso 41 e com o `CloneValue` de A2. Vale para qualquer membro com nome de método sintetizado do record (`Equals`, `GetHashCode`, `ToString`, `PrintMembers`, `Deconstruct`, `EqualityContract`). Primeiro uso: `AlterTableOperation.Algorithm/Lock/AutoIncrement`.
4. **Função livre que retorna `impl fmt::Display` com struct local** (`display_constraint_name`, `display_option`): método `internal static IDisplay X(...)` em `DdlModule`; o struct local vira `private sealed class` aninhada na classe do módulo, no estilo de `DisplaySeparated<T>` (propriedades `Value`/nomes do caso 35, `Fmt`, `ToString()`). `T: fmt::Display` → genérico sem restrição (o handler aceita `IDisplay`, `string`, inteiros etc.); `&Option<T>` → `T?`. `#[must_use]` não tem equivalente e não é traduzido (só citado no comentário). Primeiro uso: `DdlModule.A5.cs`.
5. **Igualdade com variante unitária** (`self.data_type == DataType::Unspecified`) → teste de tipo `DataType is Ast.DataType.Unspecified` (mesmo resultado, sem alocar). Primeiro uso: `ColumnDef.cs`.
6. **Struct `Copy` da AST com `derive(Default)`** (`ConstraintCharacteristics`): `sealed record` (caso 36) + `static Default()` (caso 42), e não `readonly record struct` (o caso 6 vale para tipos pequenos do tokenizer com `Ord` usado). Consequência: `Option<ConstraintCharacteristics>` → `ConstraintCharacteristics?` (referência anulável).
7. **`match` sobre tupla de `Option`s** (`ConstraintCharacteristics::fmt`): `switch (a, b, c)` com padrões `null`/`{ } x`, na ordem do Rust, mais `default: throw` (como o decidido em A2). As ligações do Rust que repetiriam o nome das variáveis externas (`deferrable`, `enforced`; C# não permite sombreamento) ganharam o sufixo `Text`.
8. **`let (a, b) = match self { V(p) => ("X", p), .. }`** (`IdentityPropertyKind`, `ColumnPolicy`): `var (a, b) = this switch { V { Value: var p } => ("X", p), .., _ => throw };`.
9. **`write!(f, "")`** → nada, com comentário no lugar (segui a decisão 4 de A2). Primeiro uso aqui: `KeyOrIndexDisplay`.
10. **`Option<Vec<T>>`** → `Sequence<T>?` (`Nullable<Sequence<T>>`), aplicação direta de §5 + caso 31; uso `if (x is { } v)`. Ex.: `AlterPolicyOperation.Apply.To`, `ColumnOption.Generated.SequenceOptions`, `ClusteredBy.SortedBy`.
