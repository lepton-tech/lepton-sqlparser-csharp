## Decisões (para convencoes.md §13)

1. **CS8866 com a propriedade de um parâmetro posicional** (aplicação da regra 1 do integrador). A propriedade é declarada explicitamente com `new`, mantendo o nome mecânico: `public sealed record IsFalse(Expr Value) : Expr { public new Expr Value { get; init; } = Value; }`. O CS8866 aparece sempre que o record aninhado herda um membro com o nome do parâmetro. A regra 1 cobre o caso "campo com o nome de outra variante". Aqui ele apareceu também em duas formas que a regra precisa mencionar:
   - **(a) variante-tupla de 1 campo (`Value`) num enum que tem uma variante chamada `Value`.** Em `Expr`, toda variante-tupla herda a variante aninhada `Expr.Value`.
   - **(b) campo com o nome de um método herdado da base.** `ConditionalStatements::Sequence { statements }` × `fn statements()`.

   Onde foi aplicado:
   - `Expr`, por causa da variante `Value`: as 27 variantes-tupla `Identifier`, `CompoundIdentifier`, `IsFalse`, `IsNotFalse`, `IsTrue`, `IsNotTrue`, `IsNull`, `IsNotNull`, `IsUnknown`, `IsNotUnknown`, `Nested`, `TypedString`, `Function`, `Subquery`, `GroupingSets`, `Cube`, `Rollup`, `Tuple`, `Dictionary`, `Map`, `Array`, `Interval`, `Wildcard`, `OuterJoin`, `Prior`, `Lambda` e `MemberOf`, e ainda os campos `JsonAccess.Value` e `Prefixed.Value`.
   - `Expr`, por causa da variante `Subquery`: `InSubquery.Subquery` e `Exists.Subquery`.
   - `ConditionalStatements.Sequence.Statements` (forma b).

   A regra 2 do integrador (`clone` → `CloneValue`) não ocorre neste trecho.
2. **`impl Deref<Target = [T]>` + `impl AsRef<[T]>` + `impl IntoIterator` (por referência e por valor) num enum** (`OneOrManyWithParens<T>`). A base `abstract record` implementa `IReadOnlyList<T>`:
   - `len()` → `Count`; `x[i]` → indexador; `for` → `foreach`.
   - O `match` do `deref` fica num único método privado `AsSlice()`.
   - O tipo iterador por valor (`OneOrManyWithParensIntoIter<T>`, seu enum interno e os `impl Iterator`/`FusedIterator`/`ExactSizeIterator`/`DoubleEndedIterator`) não é portado: `next_back`/`rev`, `count` e `fold` correspondem a `Reverse()`, `Count()` e `Aggregate()` do LINQ.

   Complementa o caso 34, que trata do `Deref` para um campo.
3. **`match` sobre tupla** (`match (&self.leading_field, self.leading_precision, ..) { (Some(DateTimeField::Second), Some(lp), Some(fsp)) => .., _ => .. }`) → `switch ((LeadingField, LeadingPrecision, FractionalSecondsPrecision)) { case (DateTimeField.Second, { } lp, { } fsp): .. default: .. }` (`Interval.cs`).
4. **`match` interno sobre `Option`** (`match escape_char { Some(ch) => .., _ => .. }`) → `switch` aninhado com `case { } ch:` / `default:`. Assim, cada `match` continua sendo um `switch`.
5. **`format!("{m}")` dentro de um `Display`** (`Set::SetRole`, `Set::SingleAssignment`: `context_modifier.map(|m| format!("{m}")).unwrap_or_default()`) → `x is { } m ? Formatter.Format(m) : ""`. É a tradução literal do `format!`, que cria um formatador novo sem `#`. Esclarece o caso 30: o "não use `ToString()`/format" não se aplica quando o próprio Rust usa `format!`.
6. **Desestruturação no início do `fmt`** (`let CaseStatement { case_token: _, match_expr, .., end_case_token: AttachedToken(end) } = self;`) → locais com os nomes Rust (`var matchExpr = MatchExpr; var end = EndCaseToken.Value;`) e o comentário com o `let` original.
7. **Igualdade com variante unitária de enum com `Display`** (`op == &UnaryOperator::PGPostfixFactorial`) → `op is UnaryOperator.PGPostfixFactorial`. `matches!(op, A | B)` → `op is A or B` (caso 13).
8. **`Option<Vec<T>>`** → `Sequence<T>?` (`Nullable<Sequence<T>>`), para distinguir `None` de `Some(vec![])`: `StructField.Options`, `Expr.Trim.TrimCharacters`, `Analyze.Partitions`.
9. **`#[cfg_attr(feature = "recursive-protection", recursive::recursive)]`** em `fn fmt` → não traduzido. Fica só um comentário no local (ver Divergências).
10. **Enums C# da regra 1 da §6** (`CastKind`, `ExtractSyntax`, `LambdaSyntax`): `switch` com `default: throw`; nunca são interpolados no `Formatter`.

## Divergências

- **Proteção contra recursão (candidata a DIV).** No Rust, a feature padrão `recursive-protection` faz o `Expr::fmt` (e o parser) crescer a pilha sob demanda (`recursive::recursive`). O C# não tem isso. Uma expressão muito profunda (milhares de níveis) pode causar `StackOverflowException`, que o .NET não deixa capturar. O texto gerado é o mesmo. Sugestão: o integrador decide junto com o limite de recursão do parser (`recursion_limit`).
- Nenhuma divergência de saída `Display`. A peculiaridade do Rust no `ILIKE ... ESCAPE` (`"ANY"` sem espaço depois) foi mantida, com um comentário no código.
