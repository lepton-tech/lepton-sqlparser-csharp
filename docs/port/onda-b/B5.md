## Decisões (para convencoes.md §13)

1. **`Result` guardado sem `?` e desembrulhado com `objects?` em vários braços de um `match`** (`parse_grant_deny_revoke_privileges_objects`): o `try/catch` da decisão 4 da B1 guarda o valor e a exceção (`objectsResult`, `objectsError`), e uma função local `UnwrapObjects()` relança o erro no ponto de cada `objects?`. O braço que não usa o valor (`Some(unexpected_keyword) => return Err(..)`) descarta o erro, como no Rust.
2. **O mesmo padrão dentro de uma closure** (`let values = parser.parse_comma_separated0(..); parser.expect_token(&RParen)?; values` em `parse_key_value_option`): a lambda guarda o resultado e a exceção, executa o `ExpectToken` (cujo erro tem precedência) e só então relança. Decisão 4 da B1, sem mudança.
3. **`bool | bool` (sem curto-circuito) em guarda de `match`** (`self.peek_keywords(..) | self.peek_keyword(LIMIT)` em `maybe_parse_show_stmt_in`): mantido como `|` no C#, que também avalia os dois lados.
4. **`vec.insert(0, x)` / `vec.pop()` sobre o campo `Vec` de um record** (`parent_name.0.insert(0, ..)` em `maybe_parse_show_stmt_in`; `name.0.pop().unwrap()` em `parse_grantee_name`): `insert` → nova `List<T>` a partir da `Sequence`, `Insert(0, x)` e `with { Value = lista.ToSequence() }` (família da decisão 11 da B4); `pop()` seguido de descarte do record → leitura do último elemento (`Value[Count - 1]`), como a decisão 15 da B1.
5. **`<[T; 1]>::try_from(vec)`** (`parse_concat_pattern`): `if (lista.Count == 1) return lista[0];` e, no `Err(patterns)`, a própria lista convertida em `Sequence`.
6. **Padrão de fatia com ligação do resto** (`match &idents[..] { [] => .., [first, idents @ ..] => .. }` em `parse_optional_select_item_except`): `if (idents.Count == 0) .. else` com `idents[0]` e `idents.Skip(1).ToSequence()`. Os padrões de lista do C# com `..` ligado exigem `Slice`/`Range`, que `Sequence<T>` não tem.
7. **`match` sobre tupla `(bool, Token)` com guarda** (`parse_execute`) e sobre `(bool, bool)` exaustivo (`parse_duplicate_treatment`): `switch` sobre tupla C# com padrões posicionais (caso 63). O compilador aceita os dois como completos para atribuição definida e retorno (conferido na cópia com *stubs*).
8. **`match` sobre `enum` C# (`IsLateral`, `ParserSupportTypes.cs`) usado como expressão** (`lateral: match lateral { Lateral => true, NotLateral => false }`): expressão `switch` com braço `_ => throw new InvalidOperationException(..)`. Sem o descarte, o C# avisa (CS8524) que valores não nomeados do `enum` não são cobertos, o que quebraria o build com `TreatWarningsAsErrors`.
9. **`let x = loop { .. break Some(v); .. break None; }`** (`parse_table_function_args`): local declarada antes do `while (true)` e atribuída imediatamente antes de cada `break`.
10. **`break`/`continue` do `loop` dentro de `match` usado como instrução** (`parse_key_value_options`): flag `stop` (decisão 1 da B4) para os `break`; o `continue` do braço `Token::Comma` fica como `continue` na seção do `switch` (no C#, `continue` dentro de `switch` vale para o laço externo).
11. **Closure que altera variável capturada** (`explicit_row = true` em `parse_values`): a lambda C# captura e altera o local, com a mesma semântica. O valor é lido depois de `ParseCommaSeparated`, como no Rust.
12. **`pub fn index(&self) -> usize`** → método `public int Index() => _index;` (no `Parser`, `fn` sem parâmetros continua método; a regra de propriedade da §7 é só do `Dialect`). **`pub fn into_tokens(self) -> Vec<TokenWithSpan>`** → `public List<TokenWithSpan> IntoTokens() => _tokens;`: devolve a própria lista interna, sem cópia, porque o Rust consome o parser; o tipo é o mesmo de `WithTokensWithLocations(List<TokenWithSpan>)`.
13. **`String::chars().next()` guardado num campo `char` que virou `string`** (`UserDefinedTypeSqlDefinitionOption::Category`, nomes.md): primeiro scalar value, `char.IsSurrogatePair(s, 0) ? s.Substring(0, 2) : s.Substring(0, 1)`; string vazia → o `ParserError` do `ok_or_else`.
14. **Guardas que consomem tokens** (`Token::Number(n, _) if self.consume_token(&Token::Comma)`, `FunctionArgExpr::Expr(expr) if .. && self.parse_keyword(AS)`, `expr if .. && self.consume_tokens(&[Period, Mul])`): `case .. when ..` na mesma ordem dos braços (decisão 6 da B3), com comentário no código.
15. **`matches!(self.peek_tokens_ref(), [TokenWithSpan { token: .., .. }, ..])`** (`peek_subquery_or_cte_start`): padrão de lista sobre `PeekTokensRef(2)` com padrões de propriedade (`{ Token: Token.LParen }`), extensão da decisão 3 da B4.
16. **Identificadores contextuais** `or` e `when` (palavras de padrões e de `catch`/`case` no C#) → `@or`, `@when` (decisão 14 da B2), além dos já usados `@into`, `@on`, `@from`, `@using`, `@default`, `@with`, `@params`, `@operator`, `@explicit` e o reservado `@namespace`.
17. **`Lock` sem qualificar**: o retorno de `parse_lock_statement` fica `Lock`, como a B1 supôs. Conferido na cópia com *stubs*: no `netstandard2.0` (com PolySharp) não há ambiguidade com `System.Threading.Lock`, então o caso 49 não se aplica.
