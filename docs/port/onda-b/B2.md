## Decisões (para convencoes.md §13)

1. **`.ok()` sobre `Result`** (`self.parse_identifier().ok()`, `self.parse_object_name(..).ok()`): `try { x = ParseX(); } catch (ParserException) { x = null; }`, **sem** restaurar `_index` (o `.ok()` só descarta o erro; quem restaura a posição é o `maybe_parse`). Usado em `ParseCreateSecret`, `ParseCreateTrigger`, `ParseDropSecret` e `ParseCreateTable`.
2. **`#[derive(Default)] struct` local dentro de `fn`** (`Body` em `parse_postgres_create_function`): classe `private sealed class Body` aninhada no `Parser`, com o nome mecânico e campos públicos mutáveis, declarada logo antes do método que a usa; `Body::default()` → `new Body()`. Mesma ideia do caso 67 (structs aninhados em `fn fmt`).
3. **`fn` aninhada genérica** (`fn ensure_not_set<T>(field: &Option<T>, name: &str) -> Result<(), ParserError>`, declarada dentro do `loop`): função local `static void EnsureNotSet<T>(T? field, string name) where T : class`, declarada uma vez no método (todos os `T` usados são tipos-referência). `fn` aninhada passada a `maybe_parse` (`parse_data_type_no_default`, `parse_data_type_for_aggregate_arg`): função local `static`, passada como grupo de método com o tipo explícito (`MaybeParse<DataType>(ParseDataTypeNoDefault)`), como a decisão 9 da B1.
4. **`parser_err!(MSG, self.peek_token_ref())`** (o segundo argumento é um `TokenWithSpan`, não uma `Location`; `parse_create_table_on_commit`): `throw new ParserException(new ParserError.ParserErrorValue(MSG + PeekTokenRef().ToString()))`. O `format!("{}{}", ..)` da macro escreve o `Display` do token (sem " at Line: .."); `ParserErr` só aceita `Location`.
5. **Braço de `match` com padrão `|` que liga variável** (`Token::Word(Word { value: name, .. }) | Token::SingleQuotedString(name) => { corpo }`, em `parse_plain_option`): o C# não liga variáveis em padrões `or`. Um `switch` só extrai `name` (com o `_ =>` original como `default`) e o corpo do braço vem depois do `switch`, com comentário.
6. **`opt.get_or_insert_with(T::default).campo = v` sobre record imutável** (`HiveFormat` em `parse_hive_formats`): `hiveFormat = (hiveFormat ?? HiveFormat.Default()) with { Campo = v };` (caso 42 para o `Default`).
7. **`let (a, b, c) = if .. { (x, y, z) } else { .. };`** (`parse_snowflake_declare`, `parse_mssql_declare_stmt`, `parse_create_extension`): locais declarados antes do `if`, atribuídos em cada ramo (direto ou por desconstrução `(a, b) = (x, null)`). Quando um elemento da tupla Rust é avaliado depois de outra chamada (`(self.parse_snowflake_variable_declaration_expression()?, Some(data_type))` com `data_type` lido antes), a ordem das chamadas é mantida com locais intermediários.
8. **`{kw}` × `{kw:?}` de `Keyword` em mensagens**: `Display` → `kw.ToSql()` (caso 3), `Debug` → `kw.ToString()` (caso 46), sempre explícitos na interpolação para deixar a diferença visível (`unexpected keyword \`{unexpectedKeyword.ToSql()}\` in trigger period` × `got {unexpectedKeyword.ToString()}`). O braço ligado `unexpected_keyword =>` de um `match` exaustivo vira `case var unexpectedKeyword:` (o C# considera o `switch` completo; não é preciso `default`).
9. **`ALL_KEYWORDS.binary_search(&s).is_err()`** (`parse_snowflake_declare`): `Keywords.Lookup(s) == Keyword.NoKeyword` (caso 2). `to_uppercase()` → `ToUpperInvariant()` (DIV-001).
10. **`self.tokens.get(i).map_or(d, |t| f(t))`** (`parse_create_role`): `i < _tokens.Count ? f(_tokens[i]) : d`.
11. **`opt.ok_or_else(|| ParserError::ParserError(..))?` seguido de uso do valor** (`parse_create_operator`): `if (x is null) throw new ParserException(..);` e uso de `x` (a análise de nulidade sabe que não é nulo); sem variável nova.
12. **`option.or(other)`** (`parse_create_index`): `x ?? other`.
13. **`match b { true => .., false => .. }` sobre `bool`**: `switch (b) { case true: ..; case false: .. }` (o compilador aceita como completo para atribuição definida).
14. **Identificadores contextuais do C# usados como nomes Rust** (`with`, `into`, `from`, `async`, `not`, além dos reservados `using`, `default`, `class`, `volatile`): prefixo `@` (`@with`, `@into`, `@from`, `@async`, `@not`), estendendo o caso 56 aos contextuais que podem confundir o leitor ou o analisador (`x with { }`, consultas LINQ, padrões `not`).
15. **`Statement::X(Tipo { .. })` construído diretamente no Rust** (sem `.into()`; `parse_drop_extension`, `parse_drop_operator*`): `new Statement.X(new Tipo(..))`, como no Rust; `Statement.From(..)` só onde o Rust usa `.map(Into::into)`/`.into()` (decisão 7 da B1).
