## Decisões (para convencoes.md §13)

1. **Ordem de avaliação dos literais de struct.** O Rust avalia os campos de um literal na ordem em que aparecem no texto (ex.: `Expr::Like { negated, any: self.parse_keyword(ANY), expr, pattern: ..parse_subexpr.., escape_char: ..parse_escape_char.. }`). Na construção do record, os argumentos nomeados ficam **na ordem do literal Rust** (o C# avalia argumentos na ordem textual, mesmo nomeados fora de posição). Isso preserva os efeitos colaterais (consumo de tokens) quando o literal tem chamadas `parse_*`.
2. **Parâmetros `Vec<T>` do parser.** `mut v: Vec<T>` (posse transferida e alterada) e `&mut Vec<T>` → `List<T>` (`ParseCompoundExpr(Expr root, List<AccessExpr> chain)`, `ParseMultiDimSubscript(List<AccessExpr> chain)`, `BuildCompoundExpr`). `&[T]` e `Vec<T>` só lido, com `T` que não é `Keyword`/`Token` → `IReadOnlyList<T>` (`IsAllIdent`, `ExprsToIdents`); `&[]` → `System.Array.Empty<T>()`, `vec![]` → `new List<T>()`. O retorno continua `Sequence<T>` (caso 50).
3. **`match` sobre `Result<Option<T>>` com braços `Ok(Some)`/`Ok(None)`/`Err(e)`** (`parse_prefix_inner`): `try { r = ...; } catch (ParserException e) { <braço Err>; throw; }` seguido de `switch (r) { case { } x: ...; case null: ...; }`. Só a expressão que produz o `Result` fica no `try`; os braços `Ok` ficam fora (os erros deles propagam direto, como no Rust). `if let Ok(Some(x)) = self.maybe_parse(..)` → `try { x = MaybeParse(..); } catch (ParserException) { x = null; }` (o `Err` de limite de recursão é ignorado, como no `if let`). `if let Err(ref e) = result { cache }; result` → `try { return f(); } catch (ParserException e) { cache; throw; }`.
4. **Resultado guardado sem `?` e devolvido depois de outro `?`** (`let r = self.parse_comma_separated(..); self.expect_token(..)?; r` em `parse_duckdb_struct_type_def`): capturar a `ParserException` numa variável, executar o passo seguinte (cujo erro tem precedência) e só então relançar a exceção guardada.
5. **`Option<Option<T>>` de `maybe_parse(..)` + `.unwrap_or_default()`** (`parse_msck`): a closure devolve `Option<T?>.Some(x)` (caso 55) e o chamador faz `MaybeParseValue(..) is { } o ? o.Value : null`.
6. **Funções genéricas que só devolvem `Err`** (`fn cached_prefix_error<T>(..) -> Result<T, ParserError>`): `internal T CachedPrefixError<T>(..)`, que sempre lança, como `Expected<T>` (caso 45).
7. **`.map(Into::into)` / `.into()` para `Statement`** → `Statement.From(x)` (caso 73), inclusive `rename_tables.into()` → `Statement.From(Sequence<RenameTable>)`.
8. **`Self::metodo` de instância passado como função** (`Self::parse_utility_option`, `Self::parse_struct_field_def`, `Self::parse_dictionary_field`) → lambda `p => p.ParseX()`, como `Parser::parse_x` (caso 50).
9. **`fn` aninhada dentro de `fn`** (`validator` em `parse_expr_with_alias_and_order_by`) → função local `static` com o nome mecânico (`Validator`), passada como grupo de método. Parâmetro `_parser` mantido.
10. **`str::starts_with(char)`** → `s.StartsWith("_", StringComparison.Ordinal)` (o `netstandard2.0` não tem a sobrecarga com `char`, §11, e a sem `StringComparison` é sensível à cultura).
11. **`str::eq_ignore_ascii_case`** → `RustChar.EqIgnoreAsciiCase(a, b)` (novo membro de `Support/RustChar.cs`, caso 19): só `a-z`/`A-Z` são dobrados; `OrdinalIgnoreCase` não serve porque também dobra letras fora do ASCII.
12. **`format!("{:?}", token)`** (mensagens `No infix parser for token {:?}` e `Unexpected token in unary operator parsing: {tok:?}`, verificadas por testes do Rust) → `token.ToDebugString()`, método de extensão `internal` em `Parser/TokenDebugExtensions.cs`, que reproduz o `#[derive(Debug)]` de `Token`, `Word`, `Whitespace`, `DollarQuotedString` e `QuoteDelimitedString` (variante unitária = nome do record aninhado; `Option` = `Some(..)`/`None`; strings com aspas e escapes). Extensão, e não membro de `Token`, para não alterar o arquivo do tokenizer; as chamadas não mudam se um dia virar membro.
13. **String Rust com `\` no fim da linha** (continuação que remove a quebra e a indentação seguinte; `parse_flush`) → concatenação dos pedaços **sem** o espaço (`"...OPTIMIZER_COSTS," + "RELAY LOGS ..."`), com comentário.
14. **`parser_err!(msg, { self.prev_token(); loc })`** (bloco como argumento) → as instruções do bloco antes do `throw ParserErr(msg, loc)`.
15. **`access_chain.last()` depois de checar que não está vazio / `let Some(P) = v.pop() else { return parser_err!(..) }`** → `v[v.Count - 1]`; `pop` → leitura + `RemoveAt` seguidos do teste de padrão negado (`if (x is not P) throw ParserErr(..)`). `.iter().rev().skip(1).all(..)` → `Enumerable.Reverse(v).Skip(1).All(..)` (LINQ na condição, 1:1 com o iterador).
16. **`dialect_is!(dialect is X | Y)`** → `dialect is X or Y` (igual a `dialect_of!`, caso 8). O `let dialect = self.dialect;` local é mantido.
17. **Braço de `match` duplicado e inalcançável** (`Token::SingleQuotedString | .. if w.value.starts_with('_')` aparece duas vezes em `parse_expr_prefix_by_unreserved_word`) → portado duplicado, com comentário (fidelidade, §1.4). O C# aceita porque os dois `case` têm `when`.
18. **`_ if cond => match ..` dentro de `match` sobre `Keyword`** → `case var _ when cond:` seguido do `switch` interno; o `_ =>` final vira `default`.
19. **`switch` de instrução exaustivo sem `default`** (`case { } x: return ..; case null: return ..;`) foi conferido num projeto de rascunho com as mesmas opções do Core: o compilador considera o fim inalcançável e a variável definitivamente atribuída; não é preciso `default`.

## Divergências

- **Proposta (DIV-006, a numerar pelo integrador): escape do `Debug` de strings/char em `ToDebugString()`.** O `char::escape_debug` do Rust escapa como `\u{..}` todo caractere "não imprimível" pela tabela Unicode própria e as marcas combinantes (grapheme extend) no início; a tradução escapa só os escapes nomeados (`\t`, `\r`, `\n`, `\0`, `\\`, aspas) e os caracteres de controle (`char.IsControl`), e percorre unidades UTF-16. Afeta só mensagens de erro internas que citam um token com esses caracteres (os testes do Rust usam variantes unitárias: `ShiftLeft`, `ExclamationMark`). Impacto desprezível; não há teste afetado.
