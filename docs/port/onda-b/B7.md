## Decisões (para convencoes.md §13)

1. **`pub trait Spanned { fn span(&self) -> Span; }`** → `public interface ISpanned { Span Span(); }` em `Ast/Spans/ISpanned.cs` (namespace `SqlParser.Core.Ast`). Prefixo `I`, como `IDisplay` (caso 4). Sem membros padrão (o trait também não tem). Cada tipo implementa `public Span Span()`, um método não virtual: nos enums (`abstract record`), fica na base com `this switch` (§6.4) e as variantes herdam.
2. **Onde fica cada `impl` (rastreabilidade 1:1).** Os `impl Spanned for X` de `spans.rs` são `partial` do tipo X em `Ast/Spans/Spans.Part1..3.cs`, **na ordem de `spans.rs`**, cada um precedido de `// impl Spanned for X (spans.rs:N)` (N = linha do `impl`). Assim o arquivo pode ser comparado com o Rust de cima a baixo, como os `Parser.Part*.cs`. Para receber o método, 118 records passaram a `partial` (permitido pela tarefa); a declaração `partial` repete os modificadores do original (`public sealed partial record X : ISpanned`). `impl Spanned for TokenWithSpan` (tipo do tokenizer, namespace `SqlParser.Core`) fica num arquivo próprio, `Ast/Spans/TokenWithSpan.Spans.cs`, porque um arquivo com `namespace` de escopo de arquivo não pode declarar outro namespace. Os `impl` que no Rust estão em outros módulos (`ddl.rs`, `dcl.rs`, `table_constraints.rs`) ficam **no arquivo do próprio tipo**, na posição do `PORT-TODO` (caso 75), como no Rust; nesses o tipo já é do arquivo, então basta acrescentar `ISpanned` às bases.
3. **Tipos que já têm a propriedade `Span`** (campo `span` no Rust): `TokenWithSpan`, `ValueWithSpan`, `CommentWithSpan`. Implementação **explícita**: `Span ISpanned.Span() => Span;` (`Ident` também tem a propriedade, mas não implementa `Spanned` no Rust). Quem chama: acesso ao campo `x.span` → propriedade `x.Span`; chamada ao trait `x.span()` → `((ISpanned)x).Span()` (5 lugares: `Expr::Value`, `Expr::TypedString`, `FunctionArgumentClause::Separator`, `AlterTableOperation::AutoIncrement` sobre `ValueWithSpan`; `ConnectByKind` sobre `connect_token.0`/`start_token.0`, que são `TokenWithSpan`). Extensão rejeitada: um método de extensão `Span()` não é encontrado quando o tipo tem a propriedade de instância `Span` (CS1955), e outro nome quebraria a busca pelo nome Rust. O cast é explícito e não aloca (os três são classes).
4. **O nome `Span` dentro dos tipos com o método `Span()`.** Em contexto de expressão, o nome simples `Span` passa a ser o grupo de métodos (CS0119 em `Span.Empty()`). Nesses tipos escreve-se `Core.Span.Empty()` / `Core.Span.UnionIter(..)` (mesma forma de `TokenWithSpan.Wrap`). Em contexto de tipo (`Span x`, `new Span(..)`, `new Span?[]`, `OfType<Span>()`, retorno de função local) não precisa qualificar. Conferido antes: nenhum código existente desses tipos usava `Span.` como expressão (só `Ident` e `Value`, que não ganharam o método).
5. **`fn union_spans` (privada do módulo `spans`, sem tipo homônimo)** → `internal static class SpansModule` com `internal static Span UnionSpans(IEnumerable<Span>)` (casos 20 e 29), usada com `using static SqlParser.Core.Ast.SpansModule;`. As cópias aninhadas `fn union_spans` dentro dos `impl` de `table_constraints.rs` viram função local `static Span UnionSpans(..) => Core.Span.UnionIter(iter);` no método (decisão 9 da B1). `Span::union_iter(..)` chamado direto (`ddl.rs` `Truncate`, `ExcludeConstraint`) → `Core.Span.UnionIter(..)`.
6. **Cadeias de iteradores → LINQ (§9), com `Support/RustIter.cs`** (código próprio, `internal`): `core::iter::once(x)` / `iter::once(x)` → `Once(x)`; `a.chain(b)` → `a.Concat(b)`; `v.iter().map(f)` → `v.Select(f)`; `.flat_map(f)` → `.SelectMany(f)`; um `Option` percorrido como iterador numa cadeia (`opt.iter()`, `opt.as_ref().map(..)` dentro de `.chain(..)`) → `OptionIter(opt).Select(..)`, com duas sobrecargas (`where T : class` para `T?` referência; `where T : struct` para `Nullable<T>`, inclusive `Sequence<T>?` de `Option<Vec<T>>`); `[a, b].into_iter()` → `new[] { a, b }`; `[Option<Span>; 3].into_iter().flatten()` → `new Span?[] { .. }.OfType<Span>()` (decisão 16 da B4); `Spanned::span` passado como função → `i => i.Span()` (caso 50). `Option::map` que produz um **valor** (argumento de `union_opt`) → `x?.Span()` / `x?.Span` (dá `Span?`); `map_or(Span::empty(), f)` → `x is { } i ? f(i) : Core.Span.Empty()`; `.map(..).unwrap_or(d)` → `x?.Span ?? d`. O resultado é o mesmo do Rust (a união é calculada sobre todos os elementos; nada tem efeito colateral).
7. **`match self` → expressão `this switch { .., _ => throw new InvalidOperationException(..) }`** (precedentes `ColumnOptions.AsSlice`, `Comment.AsStr`), braços na ordem do Rust, um braço por braço Rust (inclusive os `Span::empty()` consecutivos, que não foram agrupados). Designação do padrão = nome da ligação Rust em camelCase quando há uma (`Analyze analyze => analyze.Value.Span()`); nome curto nas variantes-struct, com o padrão Rust em comentário quando há campos ignorados. Casos especiais: braço com bloco `{ if let .. { return x; } y }` (`Use::SecondaryRoles`) e `if let .. else ..` (`AlterSchemaOperation::OwnerTo`) → expressão condicional, com o Rust em comentário; padrão `|` com ligação (`TableConstraint::PrimaryKeyUsingIndex(c) | UniqueUsingIndex(c)`) → dois braços com o mesmo corpo (decisão 5 da B2); `match` interno sobre campo (`match cursor`, `match &self.kind`, `match self.kind`) → `switch` aninhado na mesma posição; `match &rows[..] { [] / [f] / [f, .., l] }` (`Values`) → padrões de lista sobre a `Sequence` (com `..` **sem** ligação basta `Count` + indexador `int`; a decisão 6 da B5 tratava do `..` ligado); `let from = match self { .. };` (`UpdateTableFromKind`) → local `@from` (decisão 14 da B2).
8. **Desestruturação inicial `let X { a, b: _, // nota .. } = self;`** → fica em comentário, completa (campos ignorados e notas `// todo`, úteis no diff com o upstream), e o corpo lê as propriedades diretamente (`With`, `Body`...). Locais só quando o Rust **renomeia** no padrão (`case_token: AttachedToken(start)`, `ObjectName(segments)`, `NamedWindowDefinition(ident, _)`, `start_token: AttachedToken(start_token)`): `var start = CaseToken.Value;` etc. (caso 78). `x.0` de `AttachedToken` → `x.Value`.
9. **Doc comments dos blocos `impl`** (`/// # partial span`, `/// # missing span`, listas "Missing spans:") → `<remarks>` no método `Span()` (não no `partial` do tipo, para não misturar com a documentação da outra parte), em inglês verbatim (inclusive o "Missing spans:ever" de `Insert`), com `<c>Tipo::Variante</c>` em vez de `cref`.
10. **Fidelidade de cobertura.** Todo braço `=> Span::empty()` foi mantido, inclusive `Statement::AlterFunction { .. } => Span::empty()` (o tipo `AlterFunction` tem `impl` próprio, também vazio) e `ColumnOption::Srid(..) => Span::empty()`.
11. **Testes.** `struct SpanTest<'a>(Parser<'a>, &'a str)` → classe privada aninhada com as propriedades `Parser` (`.0`) e `Sql` (`.1`); `get_source` usa `Substring` sobre colunas (os SQL dos testes são ASCII, então índice de byte = índice de `char`). `panic!(msg)` → `Assert.Fail(msg)`; `let P = x else { panic!(..) };` → `if (x is not P) { Assert.Fail(..); return; }`; `if let P = x { .. } else { panic!(..) }` → `if (x is P) { .. } else { Assert.Fail(..); }`; `.unwrap()` de `Option` → `x!`; `dbg!(..)` não traduzido. `assert_eq!` na ordem do Rust, salvo literal (vai na posição "expected", regra xUnit2000) e `#pragma warning disable xUnit2013` no arquivo (precedente de `AstModTests`). Strings `r#"..."#` de várias linhas → concatenação de linhas com `\n` explícito (espaços iniciais/finais definem as colunas esperadas e ficam visíveis). `(3, 3).into()` → `Location.From((3, 3))` (caso 7).
12. **`parse_with_wrapped_dialect`.** `struct WrappedDialect(MySqlDialect)` declarado dentro do teste → classe privada aninhada que **herda** de `MySqlDialect` (caso 8: equivale ao `fn dialect()` que devolve o `TypeId` interno) e repassa a `_inner` os outros 17 membros que o Rust repassa (inclusive os hooks `ParsePrefix`, `ParseInfix`, `GetNextPrecedence`, `ParseStatement` e `PeekNestedDelimitedIdentifierQuotes`). `r#"SELECT 'Wayne\'s World'"#` → string verbatim `@"..."`. `assert!(res1.is_ok())` → a chamada não lançar; `assert_eq!(res1, res2)` → `Assert.Equal(res1, res2)` sobre `Sequence<Statement>`.

## Divergências
