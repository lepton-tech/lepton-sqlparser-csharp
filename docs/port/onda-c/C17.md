## Decisões/nomes

1. **`run_parser_method` com closure que devolve `()`.** `TestedDialects.RunParserMethod` só aceita `Func<Parser, T>`. Para não mexer no `TestUtils` compartilhado, `ParserTests` tem `private static void RunParserMethod(TestedDialects, string, Action<Parser>)`, que embrulha a ação e devolve `ValueTuple.Create()` (o `()` do Rust; iguais entre dialetos, como no Rust). Candidato a sobrecarga em `TestUtils/TestedDialects.cs` se outras unidades precisarem.
2. **`assert_eq!(parser.peek_token(), Token::X)` (`TokenWithSpan` × `Token`).** → `Assert.Equal(parser.PeekToken().Token, X)`. Mesmo critério de `impl PartialEq<Token> for TokenWithSpan` (compara só o `token`; caso 21) e mensagem de falha legível, o que `Assert.True(a.Equals(b))` não daria.
3. **`peek_tokens::<N>()` + `matches!(.., [padrões])`.** → `PeekTokens(N)` (caso 28) + padrão de lista C#: `parser.PeekTokens(3) is [Token.Word { Value.Keyword: Keyword.SELECT }, Token.Word, ...]`.
4. **Submódulo de testes `mod test_parse_data_type { .. }`** → achatado em `ParserTests`, na mesma posição, delimitado por comentários (os `use` internos não têm equivalente). Os nomes dos testes não mudam.
5. **`macro_rules!` locais e `fn` aninhadas em testes** → métodos `private static` com nome PascalCase, logo antes do teste que os declara: `test_parse_data_type!` → `TestParseDataType(dialect, input, expected)`, `test_parse_schema_name!` → `TestParseSchemaName`, `test_parse_table_constraint!` → `TestParseTableConstraint`, `test_parse_multipart_identifier_error!` → `TestParseMultipartIdentifierError`, `fn mk_expected_col` → `MkExpectedCol`, `tpch_tests!` → `TpchTest(n)` + um `[Fact]` por consulta (`tpch_1`..`tpch_22`, nomes gerados pela macro).
6. **`Option::unwrap()` em teste** (`parse_optional_table_constraint().unwrap().unwrap()`, `ct.hive_formats.unwrap()`) → `x ?? throw new InvalidOperationException("called `Option::unwrap()` on a `None` value")`, com a mensagem do Rust.
7. **Resultados `Result` em testes** (complementa a tabela da skill `port-rust-tests`):
   - `assert!(x.is_ok())` → chamada direta (a `ParserException` reprova o teste com a mensagem do erro), como em `DialectTests.parse_with_wrapped_dialect`;
   - `assert!(x.is_err())` → `Assert.Throws<ParserException>(..)`;
   - `assert_eq!(result, Err(e))` → `var ex = Assert.Throws<ParserException>(..); Assert.Equal(ex.Error, e);` (ordem do Rust). Quando há `try_with_sql(..).unwrap()` antes, o parser é criado **fora** do `Assert.Throws`, para um erro do tokenizer não se confundir com o erro esperado;
   - `.unwrap_err()` dentro de closure → `Assert.Throws<ParserException>(() => ..).Error`;
   - `let ParserError::ParserError(msg) = .. else { panic!(..) }` → `Assert.IsType<ParserError.ParserErrorValue>(ex.Error).Value`;
   - `assert!(msg.ends_with(s), "..{msg}")` → `Assert.EndsWith(s, msg, StringComparison.Ordinal)` (mostra `msg` na falha; o analisador xUnit2009 desaconselha `Assert.True(msg.EndsWith(..))`).
8. **Analisadores xUnit (erros com `TreatWarningsAsErrors`).** Literal ou constante no `assert_eq!` vai na posição `expected` (xUnit2000; ex.: `Assert.Equal("t", ct.Name.ToString())`); `assert_eq!(x, None)` → `Assert.Null(x)` (xUnit2003); `assert_eq!(v.len(), 1)` → `Assert.Single(v)`. Mesmo critério da decisão 11 da B7. Nos demais `assert_eq!`, a ordem do Rust foi mantida.
9. **Strings `r#"..."#` de várias linhas** (`pretty_print.rs`, `sqlparser_comments.rs`) → concatenação de linhas com `"\n"` explícito; `.trim()` → `.Trim()`. Os `.cs` do repositório ficam em CRLF no checkout (`.editorconfig`, `* text=auto`): um raw string literal de várias linhas carregaria `"\r\n"` e mudaria o teste. Strings de uma linha com aspas usam escape comum (`"NULL AS \"quoted id\""`) ou raw de uma linha (`"""CATALOG."F(o)o. ""bar".table"""`).
10. **`#[ignore = "motivo"]`** → `[Fact(Skip = "#[ignore] no Rust: motivo")]`, corpo portado por inteiro. Não é `DIV`: o upstream também não executa o teste.
11. **`struct MyDialect` declarado dentro de várias funções de teste** (`sqlparser_custom_dialect.rs`, 4 vezes o mesmo nome) → `private static class <NomeDoTestePascal> { internal sealed class MyDialect : Dialect { .. } }`, uso `new CustomPrefixParser.MyDialect()`: mantém o nome Rust e o escopo da função. O `MyDialect` do Rust implementa o trait direto, então deriva de `Dialect` (não de `GenericDialect`). As funções livres do arquivo (`is_identifier_start`/`is_identifier_part`) viram `private static` da classe de teste e, dentro do `MyDialect`, são chamadas **qualificadas** (`SqlParserCustomDialectTests.IsIdentifierStart(ch)`): sem a qualificação o nome resolveria para o próprio override (recursão infinita). `ch.is_ascii_lowercase()` etc. → `RustChar.IsAsciiLowercase` (caso 19). Hooks: `Option<Result<Expr>>` → `Expr?` (caso 53); `Value::Null.with_empty_span()` → `new Value.Null().WithEmptySpan()`.
12. **`derive_dialect!(Novo, Base, [preserve_type_id = ..,] overrides = { .. })`** dentro de teste → `private sealed class Novo : Base` aninhada, logo antes do teste, com a macro original em comentário. Sobrescritas: `metodo = true|false` → `public override bool Metodo => valor;`; `identifier_quote_style = 'c'` / `None` → `public override char? IdentifierQuoteStyle(string identifier) => 'c';` / `=> null;` (o que o `derive` gera). `preserve_type_id` não tem efeito em C# (caso 8, DIV-002). `Novo::new()` → `new Novo()`; `d.is::<T>()` → `d is T`.
13. **`no_std_recursion.rs`**: o `#![cfg(not(feature = "std"))]` não é traduzido (o Core não tem features e o limite de recursão vale sempre; DIV-005), então os 8 testes rodam sempre. `s.repeat(n)` → `private static string Repeat(string s, int n)`. Os testes de 200 parênteses, 1024 `NOT`, 1000 `INTERVAL` e 100 subconsultas terminam com `ParserException` (sem estouro de pilha) nos três alvos.
14. **`include_str!("queries/tpch/N.sql")`** → `File.ReadAllText(Path.Combine(AppContext.BaseDirectory, "Queries", "tpch", "N.sql"), Encoding.UTF8)`. Os 22 arquivos foram copiados sem alteração de `upstream/sqlparser-rs/tests/queries/tpch/` para `tests/SqlParser.Core.Tests/Queries/tpch/` (no checkout Windows estão em CRLF; o parse não depende disso) e entram no `.csproj` como `<Content Include="Queries\tpch\*.sql" CopyToOutputDirectory="PreserveNewest" />`.
15. **Comentários (`sqlparser_comments.rs`)**: `Parser::parse_sql_with_comments` → `Parser.ParseSqlWithComments` (tupla nomeada); `Vec::from(comments)` → `comments.ToVec()` (caso 57); `Err(e) => panic!("Invalid sql script: {e}")` → `catch (ParserException e)` + `InvalidOperationException` com a mesma mensagem; `Span::new((2, 1).into(), (2, 23).into())` → `new Span(Location.From((2, 1)), Location.From((2, 23)))` (caso 7).
16. **Outros mecânicos**: `concat!("a", "b")` → `"a" + "b"`; `let d: &dyn Dialect = &TeradataDialect;` → `Dialect d = new TeradataDialect();`; `assert!(!x)` → `Assert.True(!x)` (forma do Rust); closures locais (`let div = |l, r| ..`, `let num = |n| ..`) → `Func<..>` locais com o mesmo nome; `format!("{query}")` → `$"{query}"`; `Ident { value, quote_style, span }` → construtor com argumentos nomeados `new Ident(Value: .., QuoteStyle: .., Span: Span.Empty())`; `"x".into()` para `Ident` → `Ident.From("x")`; `IndexConstraint { .. }.into()` → `TableConstraint.From(new IndexConstraint(..))`.

Nenhum nome novo de Core. Nomes só de teste: `RunParserMethod` (sobrecarga privada com `Action<Parser>`), `TestParseDataType`, `TestParseSchemaName`, `TestParseTableConstraint`, `MkExpectedCol`, `TestParseMultipartIdentifierError`, `Prettify`, `Spark`, `Teradata`, `TeradataAndGeneric`, `Repeat`, `Query`, `TpchTest`, classes de escopo `CustomPrefixParser`, `CustomInfixParser`, `CustomStatementParser`, `TestMapSyntaxNotSupportDefault`.
