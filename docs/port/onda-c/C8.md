## Falhas

Nenhuma. Os 54 testes passam nos três alvos, sem `Skip`.

Isso inclui as asserções de AST completas, que exercitam:
- `CREATE TABLE`, `CREATE FUNCTION` com corpo `$tag$`, `CREATE TRIGGER` e `DROP TRIGGER`;
- `CREATE`/`DROP`/`ALTER OPERATOR` e as variantes `FAMILY`/`CLASS`;

## Decisões/nomes

Nenhum nome novo de AST foi necessário. Os nomes não mecânicos já registrados em `nomes.md` foram usados como estão: `CreateTable.CloneValue`, `ForValues.From(FromValue, To)`, `PartitionBoundValue.Expr(Ast.Expr Value)`, `ParserError.ParserErrorValue`.

Decisões de tradução do arquivo de teste. Nenhuma altera o caso de teste.

1. **Classe própria, não `partial`.** `SqlParserPostgresTests3` é uma classe independente, como pedido para as fatias da onda C. Os helpers do arquivo Rust usados aqui foram copiados como métodos `private static`:
   - `pg()` → `Pg()`;
   - `pg_and_generic()` → `PgAndGeneric()`;
   - `check_arrow_precedence` → `CheckArrowPrecedence`, mantido na posição do Rust, entre `test_unicode_string_literal` e `arrow_precedence`.

   `test_operator` (linha 2511) não é usado nesta fatia e não foi copiado.
2. **Atalho `Name(params string[])`.** É um `private static` que equivale a `ObjectName::from(vec![Ident::new(a), Ident::new(b), ..])`, ou seja, `ObjectName.From(parts.Select(p => new Ident(p)).ToSequence())`. É só abreviação mecânica, com resultado idêntico, e reduz bastante o tamanho das ASTs esperadas de operadores. Onde o Rust usa `"x".into()`, o código ficou com a forma longa `ObjectName.From(Sequence.Of(new Ident("x")))`.
3. **`struct TestCase { sql, name, operation }` local** (em `parse_alter_type`) → array de tupla nomeada `(string Sql, string Name, AlterTypeOperation Operation)[]`, porque o C# não aceita tipos locais em métodos. As mensagens de `assert_eq!(.., "TestCase[{index}].name")` ficaram em comentário: `Assert.Equal` não aceita mensagem.
4. **`res.unwrap_err().to_string()`** → `Assert.Throws<ParserException>(..).Error.ToString()`, o `Display` de `ParserError` (`"sql parser error: ..."`). `assert!(err.to_string().contains(x), "msg {err}")` → `Assert.Contains(x, err.ToString())` (regra xUnit2009). A mensagem do Rust ficou em comentário, e o xUnit já mostra a string obtida.
5. **`panic!(..)`/`unreachable!(..)` num braço de `match` ou `let .. else`** → `throw new InvalidOperationException(<mesma mensagem>)`, conforme a tabela da skill `port-rust-tests`. O teste falha do mesmo jeito que com `Assert.Fail`. `unwrap_or_else(|e| panic!(..))` (em `exclude_as_column_name`) → `try/catch (ParserException)` que lança com a mesma mensagem.
6. **`matches!(x.as_slice(), [A { .. }, B { .. }])`** (em `parse_merge_do_nothing`) → `Count == 2 && x[0] is {..} && x[1] is {..}`, sem padrão de lista, seguindo a orientação de compatibilidade com o net48 da onda C. `matches!(stmt, Statement::AlterFunction(AlterFunction { kind: K, .. }))` → `Assert.True(stmt is Statement.AlterFunction { Value.Kind: AlterFunctionKind.K })`.
7. **Padrões aninhados do Rust** (`OperatorClassItem::Operator { strategy_number: 1, op_types: Some(OperatorArgTypes { left: DataType::Int4(None), .. }), purpose: None }`) → padrões de propriedade C# equivalentes (`{ StrategyNumber: 1, OpTypes: { Left: DataType.Int4 { Value: null }, .. }, Purpose: null }`). `Some(_)` sobre `Sequence<T>?` vira `not null`.
8. **Strings `r#"..."#` de várias linhas** (em `parse_trigger_related_functions`) → concatenação linha a linha com `\n` explícito. Assim o valor não depende do fim de linha do arquivo (CRLF no Windows) nem da remoção de indentação dos raw string literals do C#. O corpo `$emp_stamp$` esperado foi copiado do literal Rust, que já usa `\n`. A string com `\` no fim da linha (em `parse_create_table_partition_of_with_constraint`) virou uma concatenação sem quebra. As raw strings de uma linha viraram `"""..."""` (C# 11) ou `@"..."`, quando terminam em `\`.
9. **`statements.pop()`** sobre a `Sequence<Statement>` imutável → indexação a partir do fim (`statements[3]`, `statements[Count - 1]`).
10. **`format!("{dialect:?}")`** → `dialect.GetType().Name`, conforme o caso 9 de `convencoes.md` §13.
11. **Comparações de `Option<T>` com `Some(x)`** → `Assert.Equal(x, opcional)`. Quando o esperado é uma variante e o obtido é a base, o tipo vai explícito: `Assert.Equal<PartitionBoundValue>(..)`, `Assert.Equal<ForValues?>(..)`, `Assert.Equal<ParserError>(..)`. Nas sequências esperadas, o tipo do elemento também vai explícito (`Sequence.Of<AlterTableOperation>(..)`), para que o `Assert.Equal` compare `Sequence<Base>` com `Sequence<Base>`.
12. **Literais na posição "expected"** (regra xUnit2000). `assert_eq!(n, v.len())` → `Assert.Equal(n, v.Count)`, com `#pragma warning disable xUnit2013` no arquivo, como em `AstModTests`/`SpansTests`.
13. **`Find-SuspiciousChars`.** Uma linha do arquivo é listada: a 373, com o valor esperado `"слон"` (cirílico, U+0441 U+043B U+043E U+043D) de `test_unicode_string_literal`. É intencional: é o mesmo literal do fonte Rust. A entrada SQL correspondente (`@"U&'\0441\043B\043E\043D'"`) foi conferida e está com as barras intactas. O emoji 🐘 (U+1F418) foi conferido byte a byte (`F0 9F 90 98`). Por ser um par substituto, o script não o lista.
