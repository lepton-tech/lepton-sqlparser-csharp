## Decisões/nomes

Nenhum nome novo de AST. As decisões abaixo são só de tradução de teste e seguem os precedentes de `AstModTests`/`SpansTests` (B7, decisão 11):

1. **Funções-atalho do arquivo** copiadas como `private static` (nomes mecânicos): `Snowflake()`, `SnowflakeWithRecursionLimit(int)` (usa `TestedDialects.WithRecursionLimit`), `SnowflakeWithoutUnescape()` (`TestedDialects.NewWithOptions(.., new ParserOptions().WithUnescape(false))`) e `SnowflakeAndGeneric()`. Ficam definidas no Rust fora da fatia (linhas 1480–1500); a classe é própria (não `partial`), como pede a divisão da onda.
2. **Analisadores do xUnit sob `TreatWarningsAsErrors`:**
   - `assert_eq!` na ordem do Rust, salvo quando um lado é literal: o literal vai na posição "expected" (xUnit2000);
   - `assert!(v.contains(&x))` → `Assert.Contains(x, v)` (xUnit2017), com a igualdade estrutural dos records (`ValueWithSpan` ignora o span, como o `PartialEq` do Rust);
   - `assert!(err.contains("Expected"), "Unexpected error: {err}")` → `Assert.Contains("Expected", err)` (xUnit2009; a mensagem do xUnit já mostra o texto);
   - `assert_eq!(x, true)` → `Assert.True(x)` (xUnit2004);
   - `assert_eq!(1, v.len())` → `Assert.Equal(1, v.Count)`, com `#pragma warning disable xUnit2013` no arquivo.
3. **Erros:**
   - `res.unwrap_err().to_string()` → `Assert.Throws<ParserException>(..).Error.ToString()`;
   - `assert_eq!(ParserError::ParserError(..), res.unwrap_err())` → `Assert.Equal<ParserError>(new ParserError.ParserErrorValue(..), ex.Error)`;
   - `.is_err()` / `.expect_err(..)` → `Assert.Throws<ParserException>(..)`;
   - `parsed.err()` (`test_parentheses_overflow`) → função local `ParseErr` que devolve `ParserError?` (`null` = `None`), comparada com `Assert.Null` / `Assert.Equal<ParserError?>(.., new ParserError.RecursionLimitExceeded())`.
4. **`match`/`let .. else`:**
   - `match stmt { Variante { campos, .. } => .., _ => unreachable!() }` → `switch` com padrão de propriedades e `default: throw new InvalidOperationException("unreachable")`;
   - `panic!(msg)` → `Assert.Fail(msg)`;
   - `match stmts[..] { [A { .. }, B { .. }] => {} }` → teste explícito de `Count` e tipos (sem padrão de lista, para não depender de `System.Index` no net48);
   - `let Statement::StartTransaction { .. } = v.pop().unwrap() else { unreachable!() }` → `if (v.Last is not Statement.StartTransaction { .. }) throw ..` (`pop()` só lê o último elemento; a lista não é usada depois).
5. **Funções aninhadas de `test_sql_keywords_as_table_aliases`** (`assert_implicit_alias`, `assert_no_alias`) → funções locais `static` com nome mecânico. O Rust altera `alias.explicit` dentro do `select` mutável; como os records são imutáveis, o `select` é reconstruído com `with` (mesmo texto formatado). A variável local do primeiro `FROM` chama-se `firstFrom`, porque `from` é palavra contextual de consulta no C# (CS1001).
6. **Literais:**
   - `concat!(..)` → concatenação com `+`;
   - `r#"..."#` de uma linha → string comum com `\"`;
   - `r#"..\\.."#` (`ESCAPE='\\'`) → string verbatim `@"..\\.."` (duas barras, como no Rust);
   - `r#"..."#` de várias linhas (`test_begin_exception_end`, `test_create_database`) → linhas concatenadas com `\n` explícito, preservando indentação e espaços finais;
   - a continuação `\` do Rust (canônico de `test_create_database`) → pedaços concatenados com o espaço final de cada linha.
7. **Valores:**
   - `Value::X(..).with_empty_span()` → `new Value.X(..).WithEmptySpan()`;
   - `Value::X(..).into()` (para `ValueWithSpan`) → `ValueWithSpan.From(..)`;
   - `"lit".into()` (para `Ident`) → `Ident.From("lit")`;
   - `Value::Number("8".parse().unwrap(), false)` → `new Value.Number("8", false)` (sem a feature `bigdecimal`, como `TestUtils.Number`);
   - `..Default::default()` em `WildcardAdditionalOptions` → `WildcardAdditionalOptions.Default() with { OptIlike = .. }` (caso 42).
8. **`for it in a.iter().zip(b.iter_mut())`** → `a.Zip(b, (x, y) => (x, y))` com desconstrução da tupla; `into.0` / `object_name.0` → `.Value` (a `Sequence<ObjectNamePart>`).
