## Decisões/nomes

Nenhum nome novo de AST: todos os construtores seguem os records existentes (`nomes.md`), por exemplo `Distinct.DistinctValue`, `CreateTable.CloneValue`, `Expr.Value(ValueWithSpan Inner)`, `ParserError.ParserErrorValue`. Decisões de tradução dos testes, alinhadas com `AstModTests` e `SpansTests`:

1. **Ordem do `assert_eq!`:** mantida a do Rust, exceto quando um dos lados é literal: o literal vai na posição *expected* (regra xUnit2000, que o build trata como erro). Casos: `parse_mssql_delimited_identifiers` (`"foo"`), `parse_mssql_if_else` (texto do `IF`), `assert_eq!(stmts.len(), 2)` e semelhantes.
2. **`xUnit2013`** suprimido no arquivo (`#pragma warning disable xUnit2013`): `assert_eq!(x.len(), 1)` vira `Assert.Equal(1, x.Count)`, como no Rust.
3. **Strings com `\` no fim da linha** (continuação do Rust, que remove a quebra e a indentação da linha seguinte): viraram concatenações dos pedaços, uma por linha do Rust. Em `parse_create_function`, as duas strings dos casos de erro têm uma linha **sem** `\` (`RETURNS @t TABLE ()` e `RETURNS TABLE`): a quebra e os 8 espaços da linha seguinte fazem parte da string e foram mantidos como `"\n" + "        AS "`.
4. **Raw strings multilinha** (`parse_nested_slash_star_comment`, `test_tsql_no_semicolon_delimiter`): concatenações com `\n` explícito, para não depender do fim de linha do arquivo (CRLF/LF) nem da remoção de indentação dos raw string literals do C#.
5. **`matches!`** → padrões C# com *extended property patterns* (`args[0] is FunctionArg.ExprNamed { Name: Expr.Value { Inner.Value: Value.SingleQuotedString }, .. }`).
6. **`match` com `_ => unreachable!()`** → `switch` com `default: throw new InvalidOperationException("unreachable")` (tabela da skill `port-rust-tests`); **`panic!(msg)`** → `Assert.Fail(msg)`; **`let P = x else { panic!(..) }`** → `if (x is not P) { Assert.Fail(..); return; }` (ou `throw` quando o Rust usa `unreachable!()`).
7. **`assert!(!x)`** → `Assert.False(x)`; **`assert!(x.is_none())`** → `Assert.True(x is null)`.
8. **`assert_eq!(a, b, "msg {..}")`** (`test_tsql_statement_keywords_not_implicit_aliases`) → `Assert.True(a == b, "msg ... (left: .., right: ..)")`, porque `Assert.Equal` não aceita mensagem; **`.unwrap_or_else(|e| panic!(..))`** → `try`/`catch (ParserException)` que lança `Xunit.Sdk.XunitException` com a mesma mensagem; **`.expect(msg)`** → chamada direta, com o `expect` em comentário (como o `.unwrap()` da skill).
9. **`ParserOptions { trailing_commas, unescape, require_semicolon_stmt_delimiter }`** (literal de struct em `tsql()`) → construtor posicional `new ParserOptions(TrailingCommas: false, Unescape: true, RequireSemicolonStmtDelimiter: false)`.
10. **`Assert.Equal<T>` com tipo explícito** quando os lados têm tipos diferentes (`Expr` × `Expr.Identifier`, `TopQuantity?` × `TopQuantity.Expr`, `DataType?` × `DataType.Int`), para a inferência escolher a base.
11. **Literal `⛄️` em `parse_print`:** escrito literalmente (U+26C4 + U+FE0F; bytes `E2 9B 84 EF B8 8F`, iguais aos do Rust). O `Find-SuspiciousChars.ps1` lista a linha 2244 por causa do U+26C4: conferido, é o caractere do original, não um escape convertido.
12. Os auxiliares de `test_utils.rs` são chamados qualificados (`TestUtils.Number`, `TestUtils.ExprFromProjection`, `TestUtils.Only`, `TestUtils.TableAlias`, `TestUtils.TableFromName`, `TestUtils.AssertEqVec`), sem `using static`, para não colidir com tipos da AST homônimos (`Table`, `Join`, `TableAlias`).
