Decisões de tradução dos testes, nenhuma de código do Core:

1. **Funções-atalho do arquivo.** `pg()` e `pg_and_generic()` (definidas na linha 4167, dentro do trecho) viraram `private static TestedDialects Pg()` e `PgAndGeneric()` na própria classe. Cada fatia do arquivo Rust é uma classe própria, não `partial`.
2. **Ordem do `assert_eq!`.** A ordem do Rust foi mantida. Quando um dos lados é literal, o literal vai na posição `expected` (regra xUnit2000, como em `AstModTests` e `SpansTests`).
3. **Checagem de tamanho.** `assert_eq!(1, x.len())` virou `Assert.Equal(1, x.Count)`, com `#pragma warning disable xUnit2013` no arquivo, como em `AstModTests` e `SpansTests`.
4. **`Option<bool>`.** `assert_eq!(x, Some(true/false))` com `x: Option<bool>` virou `Assert.True(x)`/`Assert.False(x)`, nas sobrecargas `bool?`, que falham se o valor for `null` (xUnit2004). `assert_eq!(x, None)` virou `Assert.Null(x)`.
5. **`panic!`/`unreachable!`.** Viraram `Assert.Fail(msg)`. `let P = x else { unreachable!(..) }` virou `if (x is not P) { Assert.Fail(..); return; }`.
6. **`Option::unwrap()`.** Ganhou o helper privado `Unwrap<T>(T?)`, que lança `InvalidOperationException` com a mensagem do Rust. Uso em `select.selection.unwrap()`, `alias.unwrap()`, `stmt.first().unwrap()` e `partition_by.unwrap()`.
7. **`matches!` com guarda.** Os casos de `json_object_*` e `parse_json_object` viraram `expr is Expr.Function { Value: { .. } } && ...`, com padrões de propriedade estendidos.
8. **Padrões de fatia.** `&args[..] == &[FunctionArg::ExprNamed { .. }]` virou `args is { Count: 1 } && args[0] is FunctionArg.ExprNamed { Operator: .. }`.
9. **`parse_sql_statements(sql).as_deref()` com `Ok([Statement::CreateRole(r)])`.** Virou `statements is not { Count: 1 } || statements[0] is not Statement.CreateRole { Value: var createRole }`, seguido de `Assert.Fail`. Cada caso fica num bloco `{ }` próprio, para reaproveitar os nomes.
10. **`is_ok()` seguido de `panic!`.** O laço `negatables` virou `try`/`catch (ParserException)` com uma flag, para manter a forma do Rust.
11. **Strings com várias linhas.** O arquivo é CRLF, então as strings Rust de várias linhas viraram concatenações com `\n` explícito. São os `$$ ... $$` de `parser_create_function_with_args`, `parse_update_has_keyword` e `parse_create_table_with_alias`. A continuação `\`+quebra de linha do Rust, em `test_lateral_function_with_ordinality_and_column_aliases`, virou uma concatenação sem os espaços iniciais, como o Rust faz.
12. **Escapes `\u` em SQL.** Em `parse_escaped_literal_string`, os textos SQL que contêm `\u0001`, `\U0010FFFF`, `\u0000`, `\U00110000` e `\u{0001}` são escritos com o marcador `{BS}` e `.Replace("{BS}", Backslash)`. Assim nenhuma ferramenta de edição converte a sequência no caractere literal. Os valores esperados `"\u{0001}"`, `"\u{10ffff}"`, `"\u{000c}"` e `"\u{0002}"` usam `char.ConvertFromUtf32(0x..)`.
13. **Função aninhada.** `fn negative_cast(sqls: &[&str])`, dentro de `parse_escaped_literal_string`, virou a função local `static void NegativeCast(string[] sqls)`.
