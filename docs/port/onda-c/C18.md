## Desenho (resumo)

- **O derive vira um gerador.** `pwsh tools/codegen/Generate-Visitor.ps1` compila o Core **sem** o código gerado (`-p:SqlParserVisitorCodegen=true`), lê a AST por reflexão (ordem dos campos = construtor primário; ganchos = `[VisitWith]`), **confere tudo contra o Rust** (530 tipos com `derive(Visit)`, o `impl Visit` manual de `Ident`, nomes e ordem dos campos de cada struct e variante, as 30 anotações `visit(with)`) e escreve um `partial` por tipo em `src/SqlParser.Core/Ast/Visitor/Generated/<Pasta>.g.cs`. Qualquer divergência aborta a geração. `-Check` só verifica. Sem reflexão na biblioteca.
- **Conferência na primeira execução:** os nomes e a ordem dos campos de todos os tipos da AST C# batem com o Rust; só as variantes renomeadas já registradas (`DistinctValue`, `PasswordValue`, `EqualsVariant`) precisaram ser reconhecidas pelo gerador.
- **Traits:** `Visit` → `IVisit`; `VisitMut` → `IVisitMut<TSelf>` (`var flow = s.Visit(mutador, out s);`); `Visitor`/`VisitorMut` → classes abstratas `Visitor<TBreak>`/`VisitorMut<TBreak>` (ganchos `virtual`, `&mut T` → `ref T`); funções livres → classe estática `Visitor`; `ControlFlow<B>` → `Support/ControlFlow.cs`.
- **`VisitMut` sobre AST imutável:** o gancho troca o nó por `ref`; os pais são reconstruídos com `with` só quando a identidade do filho muda; sem mudanças, volta a mesma instância; mudanças antes de um `Break` ficam, como no Rust.
- **Poda:** só são visitados campos cujo tipo alcança algum gancho (365 dos 514 nós alcançam). O resto fica como comentário no código gerado; não tem efeito observável.
- **`recursive::recursive`:** cada `Visit`/`VisitMut` gerado testa a pilha na entrada e, se faltar, continua numa thread nova de 2 MiB (`StackGuard`). Enums despacham para um método por variante, para gastar pouca pilha por nível (o `overflow` do Rust estourava a pilha no .NET 8/10 em `Debug` antes disso).
