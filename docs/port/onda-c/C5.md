## Decisões/nomes

Nenhum nome novo de AST foi criado (nada a registrar em `nomes.md`). As decisões abaixo são de tradução de testes e convém o integrador consolidá-las em `convencoes.md` §13, se ainda não houver caso equivalente vindo das outras fatias (C1–C4).

1. **Funções auxiliares do arquivo Rust.** Copiadas como métodos `private static`, com nome mecânico, só as que a fatia usa: `ParseSqlStatements`, `OneStatementParsesTo`, `NonLeftAssociativeDialects`, `VerifiedStmt` e `VerifiedOnlySelect` (linhas 10994–11020 do Rust). `pg_and_generic`, `ms_and_generic`, `verified_query` e `verified_expr` não são usadas aqui.
2. **Construções da std do Rust sem equivalente direto** viraram auxiliares privados, documentados no arquivo:
   - `unreachable!()` / `unreachable!(msg)` → `throw Unreachable()` / `throw Unreachable(msg)` (`InvalidOperationException` com o texto do `panic` do Rust);
   - `Option::unwrap()` em referência → `Unwrap(x)`; `Vec::pop().unwrap()` → `Pop(lista)` sobre uma cópia `List<T>` da `Sequence<T>` (o Rust desestrutura com `mut`);
   - `panic!(msg)` → `Assert.Fail(msg)` (mesma regra de `SpansTests`).
3. **Testes de regressão de explosão exponencial** (`thread::spawn` + `mpsc::channel` + `rx.recv_timeout(5s).expect(msg)`): auxiliar `SpawnAndRecvTimeout(body, timeout, msg)`. A thread é criada com **2 MiB de pilha**, o tamanho padrão de `std::thread::spawn`. Se o corpo lançar exceção (o `panic!` da thread no Rust), o canal "desconecta" e o teste falha com `msg: Disconnected`; se o prazo vencer, com `msg: Timeout`, como o `expect` do Rust. `let _ = Parser::parse_sql(..)` → chamada dentro de `try { .. } catch (ParserException) { }` (descarta só o `Err`). Os seis testes terminam bem dentro do prazo nos três frameworks, sem estouro de pilha.
4. **Analisadores do xUnit** (avisos viram erro):
   - `assert_eq!(x, true/false)` → `Assert.True/False(x)` (xUnit2004), com o `assert_eq!` original em comentário;
   - literal sempre na posição "expected" (xUnit2000), como em `SpansTests`;
   - `assert_eq!(1, v.len())` fica `Assert.Equal`, com xUnit2013 suprimido por `#pragma`, como em `SpansTests`/`AstModTests`;
   - `assert!(v.iter().any(|o| ..))` → `Assert.Contains(v, o => ..)` (xUnit2012).
5. `assert_eq!(statements.len(), 2, "{sql}")` → `Assert.True(alterStatements.Count == 2, sql)`, para manter a mensagem (o `Assert.Equal` de inteiros não aceita mensagem).
6. `res = parse_sql_statements(..)` seguido de `res.unwrap_err()` → `Assert.Throws<ParserException>(..)` na própria chamada, comparando depois `ex.Error` com `ParserError.ParserErrorValue`, na ordem de argumentos do Rust.
7. `assert!(matches!(x, Pat))` e `assert_matches!(x, Pat)` → `Assert.True(x is Pat)` com padrão de propriedades (`Expr.UnaryOp { Op: UnaryOperator.Not }`).
8. `match`/`let .. else` sobre variantes → `switch` com padrões de propriedade (inclusive estendidos, `Value.OptExclude: var x`) ou `if (x is not P) throw Unreachable();`.
9. Comparações com `Option<Vec<T>>` (`Sequence<T>?`) usam o tipo explícito: `Assert.Equal<Sequence<ProcedureParam>?>(..)`.
10. Sombreamento do Rust (`let sql = ..` repetido, `let dialects = ..`) → reatribuição da mesma variável; quando o escopo interno colidiria com o externo (CS0136), nome distinto (`alterStatements`), conforme o caso 72.
11. `System.Action` qualificado no parâmetro do auxiliar: `Action` sozinho é ambíguo com `SqlParser.Core.Ast.Action` (CS0104, caso 49).
12. Strings Rust de várias linhas (`r#"..."#` e literais com quebra de linha) → concatenação com `\n` explícito, preservando a indentação exata (conferida com `cat -A`); `concat!(..)` → concatenação com `+`.
13. `sql.len() as u64 + 1` (bytes) → `sql.Length + 1`: os SQLs desses testes de span são ASCII.
14. `d.is::<MsSqlDialect>()` → `d is MsSqlDialect` (caso 8; nenhum dialeto embutido herda de outro).
15. Nomes não mecânicos já registrados e usados aqui: `Distinct::Distinct` → `Distinct.DistinctValue`; `Expr::value(..)` → `Expr.MakeValue(..)`; `Value::..into()` (para `ValueWithSpan`) → `ValueWithSpan.From(..)`.
