1. **Funções-atalho do arquivo:** `fn mysql()` → `Mysql()`, `fn mysql_and_generic()` → `MysqlAndGeneric()`, `fn table_constraint_unique_primary_ctor(..)` → `TableConstraintUniquePrimaryCtor(..)` (`private static`, mesma ordem de parâmetros; o `match` sobre `Option<KeyOrIndexDisplay>` virou expressão `switch` com `{ } d` / `null`; o `.into()` para `TableConstraint` virou `TableConstraint.From(..)`, caso 7). 2. **`match stmt { Statement::X(X { a, b, .. }) => .., _ => unreachable!() }`** → `var x = Assert.IsType<Statement.X>(stmt).Value;` + locais com os nomes Rust (`var name = createTable.Name;`). 3. **`assert!(plain_options.contains(&x))`** → `Assert.Contains(x, plainOptions)`. A forma `Assert.True(v.Contains(x))` da tabela da skill é rejeitada pela regra xUnit2017 (aviso = erro no build).
4. **`assert_eq!(x.to_string(), "lit")`** → `Assert.Equal("lit", x.ToString())`: literal na posição "expected" (regra xUnit2000, precedente em `SpansTests`/`AstModTests`). Nos demais `assert_eq!` a ordem do Rust foi mantida.
5. **`assert!(matches!(parse_sql_statements(sql), Err(ParserError::ParserError(_))))`** → `var ex = Assert.Throws<ParserException>(..); Assert.IsType<ParserError.ParserErrorValue>(ex.Error);`. **`assert!(..is_ok())`** → chamada direta (a `ParserException` derruba o teste). **`std::panic::catch_unwind(|| ..)` + `assert!(result.is_err())`** → `Assert.ThrowsAny<Exception>(..)` (o `OneStatementParsesTo` falha com `XunitException`). **`.expect_err("msg")`** de `run_parser_method` → `Assert.Throws<ParserException>(..)`.
6. **`.unwrap()` de `Option`** (`query.unwrap()`, `as_select().unwrap()`, `insert_alias.unwrap()`, `first().unwrap()`, `pop().unwrap()`) → operador `!` (um `null` derruba o teste, como o `panic!`). `vec.pop()` → `Sequence.Last`.
7. **`Some(vec![..])` comparado com `Option<Vec<T>>`** (`insert_alias.col_aliases`, `Sequence<Ident>?`) → `Assert.Equal((Sequence<Ident>?)Sequence.Of(..), ..)`, para comparar como `Nullable` e distinguir `None` de `Some(vec![])` (caso 64).
