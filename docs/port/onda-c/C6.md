## Decisões/nomes

Nenhum nome novo para `nomes.md`: todos os tipos, variantes e parâmetros usados são os mecânicos (ou já registrados, como `Statement.Comment.CommentValue`, `Subscript.Index.IndexValue`, `Expr.MakeValue`). Decisões de tradução de teste (candidatas a `convencoes.md` §13 ou à skill `port-rust-tests`; não editei os documentos compartilhados para não conflitar com as outras unidades da onda):

1. **Fatia = classe própria.** `SqlParserPostgresTests1` não é `partial`. As funções-atalho do arquivo usadas na fatia são copiadas como `private static` com o nome mecânico, mesmo quando definidas fora do intervalo de linhas (`pg()`, `pg_and_generic()`). Parâmetro Rust `operator` → `@operator` (caso 56).
2. **Ordem dos argumentos do `Assert`.** `assert_eq!(a, b)` → `Assert.Equal(a, b)` na ordem do Rust, exceto quando um lado é literal: o literal vai para "expected" (xUnit2000; ex.: `assert_eq!(name.to_string(), "tab")` → `Assert.Equal("tab", name.ToString())`). `assert_eq!(None, x)` e `assert!(x.is_none())` → `Assert.Null(x)` (xUnit2003). `assert!(v.is_empty())` → `Assert.True(v.IsEmpty)`. `assert_eq!(v.len(), 1)` → `Assert.Equal(1, v.Count)`, com `#pragma warning disable xUnit2013` no arquivo (como em `AstModTests`/`SpansTests`).
3. **`Assert.Equal<T>` com tipo explícito** quando um lado é a variante e o outro a base (`Assert.Equal<Statement>(stmt, new Statement.Set(..))`, `<Expr>`, `<SelectItem>`, `<OnConflictAction>`, `<IndexType>`) e quando o valor obtido é `Option<Vec<T>>` (`Assert.Equal<Sequence<SelectItem>?>(Sequence.Of<SelectItem>(..), returning)`). Nos casos em que a inferência resolve sozinha para a base (`Assert.Equal(stmt, new Statement.Copy(..))`), o tipo ficou implícito; o resultado é o mesmo.
4. **`match` com padrão de struct → `switch` com padrões de propriedade.** Os campos fixados no padrão Rust viram subpadrões: `if_not_exists: false` → `IfNotExists: false`; `predicate: None` → `Predicate: null`; `using: Some(using)` → `Using: { } usingValue` (`using` é palavra reservada); `name: Some(ObjectName(name))` → `Name: { Value: var name }`; `inherits: Some(inherits)` sobre `Option<Vec<_>>` → `Inherits: { } inherits` (desembrulha o `Nullable<Sequence<T>>`). O `..` do Rust não tem tradução (os campos não citados são ignorados). Campos ligados sem restrição são lidos direto do record (`createIndex.Unique`) em vez de virarem locais.
5. **Braços de falha.** `_ => unreachable!()` → `default: Assert.Fail("internal error: entered unreachable code"); break;` (a mensagem do `panic` do Rust); `unreachable!("msg")` → mesma mensagem com `: msg`; `other => panic!("msg {other:?}")` → `Assert.Fail($"msg {other}")` (o `Debug` vira o `Display`/`ToString()`). Quando o `match` produz um valor usado depois (`let sub_stmt = match stmt { .. => statement, _ => unreachable!() }`, `let with_options = match table_options { .. }`), o braço vira `Assert.Fail(..); return;`, que satisfaz a atribuição definida. `let P = x else { panic!(..) };` → `if (x is not P) { Assert.Fail(..); return; }` (como em `SpansTests`).
6. **Padrão de fatia `match &v[..] { [P(c)] => .. }`** → `if (v.Count == 1 && v[0] is P { Value: var c }) { .. } else { Assert.Fail(..); }`. Não usei padrões de lista do C# para não depender de `System.Index` no net48.
7. **Erros.** `res.unwrap_err()` comparado a `ParserError::ParserError(msg)` → `var res = Assert.Throws<ParserException>(() => ..ParseSqlStatements(sql)); Assert.Equal(new ParserError.ParserErrorValue(msg), res.Error);` (skill). `assert!(matches!(res, Err(ParserError::ParserError(_))))` → `Assert.Throws<ParserException>` + `Assert.IsType<ParserError.ParserErrorValue>(ex.Error)`. `assert!(parser.parse_sql_statements(sql).is_err(), "msg")` → `Assert.Throws<ParserException>(..)` (a mensagem personalizada do Rust fica em comentário; `TestedDialects.ParseSqlStatements` converte `TokenizerException` em `ParserException`, como o `?` do Rust).
8. **Strings.** Strings Rust com várias linhas → `\n` explícito (o arquivo é CRLF, conforme `.editorconfig`; nenhuma string C# atravessa linhas). Continuação com `\` no fim da linha → concatenação dos pedaços sem a quebra e sem a indentação seguinte; isso inclui a tabulação no início da linha 223 (`\` também a remove). A tabulação literal no SQL de entrada (linha 217) e as dos dados do `COPY ... FROM stdin` (raw string `r#"..."#`) → `\t`; `\N` e `\\.` da raw string → `"\\N"` e `"\\\\."`.
