## Decisões/nomes

Nenhum nome novo de AST. As decisões abaixo são de tradução de testes e não estão cobertas pela skill `port-rust-tests`:

1. **Classe própria por fatia (não `partial`).** A skill fala em `partial class` para `sqlparser_common.rs`. Por instrução do coordenador da onda C, cada fatia é uma classe independente, para que fatias paralelas nunca conflitem. Por isso as funções de arquivo usadas aqui foram **copiadas** como métodos `private static`:
   - definidas fora das linhas 1–4319 (10994–11020): `ParseSqlStatements`, `OneStatementParsesTo`, `VerifiedStmt`, `VerifiedQuery`, `VerifiedOnlySelect`, `VerifiedExpr`, no fim da classe;
   - definidas dentro da fatia, na posição do Rust: `PgAndGeneric`, `MsAndGeneric` (sem uso nesta fatia, mas é função de arquivo das linhas 1717–1726), `AllDialectsButPg`, `GenNumberCase`, `GenSignNumberCase`, `GenNumberCaseWithSign`.
2. **`fn` local dentro de um teste** (`check_one`, `chk`) → função local `static` do C#, com nome mecânico (`CheckOne`, `Chk`). **Closures** (`check`, `expect_or_clause`, `arrow_k`, `t_a`, `expected_eq`) → funções locais (`Check`, `ExpectOrClause`, `ArrowK`, `TA`, `ExpectedEq`).
3. **`#[cfg(feature = "bigdecimal")]`:** só a variante sem a feature foi portada, com comentário (`Value::Number` guarda o texto; DIV-006, conforme o coordenador da onda C; o ID ainda não consta do `docs/port/divergencias.md` deste worktree, e o integrador deve conferir). Casos: `parse_numeric_literal_underscore` (canônico `SELECT 10_000`), `parse_select_expr_star` (`SELECT 2. * 3 FROM T`), `parse_number`, `parse_ceil_scale` e `parse_floor_scale` (`2.to_string()` → `2.ToString(CultureInfo.InvariantCulture)`).
4. **`only(&select.into)`** (`only` sobre um `Option`): a opção vira uma coleção de 0 ou 1 item antes de `TestUtils.Only` (`select.Into is { } into ? new[] { into } : System.Array.Empty<SelectInto>()`).
5. **Desestruturação de `match`/`let ... else`:**
   - `match stmt { Statement::Insert(Insert { a, b: Some(x), .. }) => .., _ => unreachable!() }` → `switch` com padrão de propriedades (`case Statement.Insert { Value: { Source: { } source } insert }:`) e `default: throw new InvalidOperationException("unreachable!()")`;
   - guarda `if optimizer_hints.is_empty()` → `when update.OptimizerHints.IsEmpty`;
   - `let P = x else { unreachable!(..) }` → `if (x is not P) throw new InvalidOperationException(..)`;
   - `bad_stmt => unreachable!("..{:?}", bad_stmt)` → `case var badStmt: throw ...` com o `ToString()` do statement (o C# não tem `Debug`).
6. **`assert!(matches!(..))` e `assert_matches!(..)`** → `Assert.True(x is ...)` com o mesmo padrão (inclusive padrões aninhados como `Expr.Value { Inner.Value: Value.SingleQuotedString }`).
7. **`panic!(msg)`** → `Assert.Fail(msg)` em contexto de instrução. Em expressão `switch` (`parse_exponent_in_select`, `match select.pop().unwrap() { .., _ => panic!("Expected: Query") }`) → `throw new InvalidOperationException(msg)`, porque `Assert.Fail` não é expressão.
8. **Erros:**
   - `assert_eq!(ParserError::ParserError(m), res.unwrap_err())` → `Assert.Equal(new ParserError.ParserErrorValue(m), Assert.Throws<ParserException>(..).Error)`;
   - `assert!(ast.is_err())` (`run_parser_method`) e `.expect_err(msg)` → `Assert.Throws<ParserException>(..)` (a mensagem do `expect_err` só aparece se o Rust falhar; vira comentário);
   - `assert!(res.unwrap_err().to_string().contains(m))` → `Assert.Contains(m, err.ToString())` (o xUnit2009 proíbe `Assert.True(s.Contains(..))`);
   - `assert!(matches!(err, ParserError::ParserError(_)))` → `Assert.True(err is ParserError.ParserErrorValue)`;
   - `Parser::parse_sql(&d, sql).unwrap_err()` → `Assert.Throws<ParserException>(() => Parser.ParseSql(d, sql)).Error`.
9. **`.unwrap()` de resultado de parse esperado OK** (`dialects.parse_sql_statements(..).unwrap()` em `parse_select_wildcard_with_alias`) → chamada direta; uma exceção falha o teste.
10. **`assert_eq!`:** ordem do Rust mantida; quando um lado é literal (`assert_eq!(table.to_string(), "t".to_string())`), o literal vai para a posição *expected* (xUnit2000). `assert_eq!(x, None)` → `Assert.Null(x)`; `assert!(x.is_some())` → `Assert.True(x is not null)`; `assert_eq!(x, Some(false))` com `bool?` → `Assert.False(x)` (xUnit2004). `assert_eq!(1, v.len())` mantido como `Assert.Equal(1, v.Count)`, com `#pragma warning disable xUnit2013` no arquivo (como em `AstModTests`/`SpansTests`).
11. **Comparação de fatias** (`assert_eq!(&[..], &args[..])`, `rows.as_slice()`) → arrays C# (`new FunctionArg[] { .. }` × `list.Args.ToArray()`), comparados elemento a elemento pelo xUnit.
12. **`find_map`/`find`/`all`/`zip`/`split`** → LINQ (`Select(..).FirstOrDefault(..)`, `FirstOrDefault`, `All`, `Zip` **com seletor**, por causa do net48, e `Split(new[] { ", " }, StringSplitOptions.None)`).
13. **Strings Rust com `\` no fim da linha** → concatenação sem a quebra nem a indentação seguinte. Em `parse_create_table`, as linhas **sem** `\` mantêm `"\n"` explícito e os 15 espaços de indentação da linha seguinte (conferido com `cat -A` no Rust).
14. **`format!("{}{}", op, value)` com `UnaryOperator`** → interpolação C# `$"{op}{value}"`, que usa o `ToString()` selado (o `Display`).
15. **`dialect.is::<X>()`** → `d is X`; `d.supports_x()` sem parâmetros → propriedade `d.SupportsX` (convencoes.md §7); `d.is_column_alias(&Keyword::RETURNING, &mut Parser::new(d))` → `d.IsColumnAlias(Keyword.RETURNING, new Parser(d))`.
