## Decisões/nomes

Decisões de tradução **só de teste** (nada mudou na API do Core). Para o integrador consolidar em `convencoes.md` §13 / skill `port-rust-tests`, se aprovar.

1. **Funções-atalho do arquivo** (`duckdb()`, `duckdb_and_generic()`, `databricks()`, `databricks_and_generic()`, `hive()`, `hive_and_generic()`, `redshift()`, `redshift_and_generic()`, `oracle()`) → `private static TestedDialects` com o nome mecânico (`DuckDb()`, `DuckDbAndGeneric()`, `Databricks()`, `DatabricksAndGeneric()`, `Hive()`, `HiveAndGeneric()`, `Redshift()`, `RedshiftAndGeneric()`, `Oracle()`), **na mesma posição do Rust**: no Hive ficam no fim da classe; no Redshift, logo depois de `parse_delimited_identifiers`.
2. **Outros auxiliares do arquivo:** `fn column_defs(statement) -> Vec<ColumnDef>` (DuckDB) → `private static Sequence<ColumnDef> ColumnDefs(Statement)`, depois de `test_struct`, como no Rust. `fn quote_delimited_string(..) -> QuoteDelimitedString` (Oracle) → `private static Ast.QuoteDelimitedString QuoteDelimitedString(char, string, char)`: o método tem o nome mecânico, igual ao do tipo, por isso o tipo é escrito qualificado (`Ast.QuoteDelimitedString`) no retorno e no `new`.
3. **`fn` aninhada dentro de um teste** (`verify_table_name_with_alias` em `test_insert_with_table_alias`) → função local `static void VerifyTableNameWithAlias(..)` no mesmo lugar do teste (caso 67), e não método da classe: no Rust ela só existe dentro do teste.
4. **Asserções** (mesmas regras de `onda-b/B7.md`, decisão 11):
   - `assert_eq!(a, b)` → `Assert.Equal(a, b)` na ordem do Rust, salvo literal/constante, que vai para a posição "expected" (xUnit2000; ex.: `assert_eq!(name.to_string(), "my_table")` → `Assert.Equal("my_table", name.ToString())`).
   - `assert_eq!(x, None)` → `Assert.Null(x)` (xUnit2003); `assert!(x.is_none())` / `assert!(x.is_some())` → `Assert.Null(x)` / `Assert.NotNull(x)`; `assert!(!x)` → `Assert.False(x)`.
   - `assert_eq!(1, v.len())` → `Assert.Equal(1, v.Count)`, com `#pragma warning disable xUnit2013` no arquivo (DuckDB, Databricks, Redshift, Oracle), como em `AstModTests`/`SpansTests`.
   - `assert_eq!(x, Some(y))` → `Assert.Equal(x, y)` (o `null` do C# já representa `None`); `Option<Vec<T>>` comparado com `Sequence<T>` funciona pela igualdade estrutural de `Sequence<T>`.
   - Mensagem extra de `assert_eq!(.., "with quote char {q:?}")` → comentário (o `Assert.Equal` do xUnit não aceita mensagem).
5. **Erros:** `.unwrap_err()` sem comparação e `assert!(..parse_sql_statements(..).is_err())` → `Assert.Throws<ParserException>(..)`; `assert_eq!(ParserError::ParserError(m), res.unwrap_err())` e `assert_eq!(res, Err(ParserError::..(m)))` → `var ex = Assert.Throws<ParserException>(..); Assert.Equal(new ParserError.ParserErrorValue(m), ex.Error);` (ou `ParserError.TokenizerError`), mantendo a ordem dos operandos do Rust.
6. **`match` com `panic!`/`unreachable!`:** `switch` com `default: throw new InvalidOperationException(msg)`. Mensagens: a do `panic!(msg)`; `"internal error: entered unreachable code"` para `unreachable!()`; `"explicit panic"` para `panic!()`; `s => panic!("Unexpected statement: {s:?}")` → `case var s: throw ..($"Unexpected statement: {s}")` (Display no lugar de Debug, só afeta a mensagem de falha). `match` em posição de expressão → expressão `switch` com `_ => throw ..`.
7. **Padrões:** desestruturação de variante-struct (`Statement::ShowCatalogs { terse, history, show_options }`, `TableFactor::Table { name, alias, .. }`, `Statement::OptimizeTable { .. }`) → `case X x:` + locais com os nomes Rust em camelCase (o padrão Rust completo fica em comentário quando há campos ignorados com `_`); padrões aninhados (`Statement::CreateTable(CreateTable { hive_distribution: HiveDistributionStyle::PARTITIONED { columns: partition_cols }, .. })`) → padrão de propriedade estendido (`Value.HiveDistribution: HiveDistributionStyle.PARTITIONED { Columns: var partitionCols }`). `assert!(matches!(x, P if guarda))` → `Assert.True(x is P && guarda)`, com `matches!` aninhado virando subpadrão (`Source: { Body: SetExpr.Select }`). `let Some(P) = e else { panic!(m) };` → `if (e is not P) { throw new InvalidOperationException(m); }`. `.as_select().map(|s| &s.from[0].relation)` → `AsSelect()?.From[0].Relation`.
8. **Construção da AST esperada:** argumentos nomeados com os nomes exatos dos records; `Default::default()` campo a campo (`test_duckdb_union_datatype`) → o valor padrão explícito (`false`, `null`, `Sequence<T>.Empty`); `WildcardAdditionalOptions { opt_exclude: .., ..Default::default() }` → `WildcardAdditionalOptions.Default() with { OptExclude = .. }` (caso 42); `Expr::value(v)` → `Expr.MakeValue(v)`; `Expr::Value(number("3").into())` → `new Expr.Value(ValueWithSpan.From(TestUtils.Number("3")))`; `"s".into()` / `Ident::from("s")` (Ident) → `Ident.From("s")`; `Ident { value, quote_style, span }` → `new Ident(Value: .., QuoteStyle: .., Span: Span.Empty())`; `MacroArg::new("a")` → `new MacroArg("a")`; `Expr::Array(Array { .. })` → `new Expr.Array(new Ast.Array(..))` (qualificado: `Array` sozinho é ambíguo com `System.Array`, caso 49); `Sequence.Of<Expr>(..)` com argumento de tipo explícito quando os elementos são variantes diferentes.
9. **Laços sobre tuplas:** `for (ast, q) in &[(..), ..]` → `foreach (var (ast, q) in new (Query, SetQuantifier)[] { .. })`; `vec![("UTINYINT", DataType::UTinyInt), ..]` → `List<(string, DataType)>`; `for &quote in &['"', '\'']` → `foreach (var quote in new[] { '"', '\'' })`; `format!("USE {quote}{name}{quote}")` → interpolação.
10. **Strings:** `r#"..."#` → string comum com `\"` ou, quando o texto tem barra invertida literal (`'it\'s'`, `'l\'auto'`), string verbatim `@"..."`. Strings Rust com `\` no fim da linha (que descarta a quebra **e** a indentação da linha seguinte) e `concat!(..)` → concatenação `+` dos mesmos pedaços, preservando o espaço antes da `\` (conferido pedaço a pedaço em `parse_quote_delimited_string`, `test_connect_by`, `test_optimizer_hints`, `test_insert_with_table_alias`, `parse_databricks_json_accessor`, `test_databricks_lambdas`). Escapes `\t`, `\n`, `\r`, `\"` do Rust são idênticos em C# (`create_delimited_table`, `parse_invalid_quote_delimited_strings`, `test_optimizer_hints`).
11. **Caracteres não ASCII:** a letra A com trema (U+00C4, `test_databricks_identifiers`) e os emojis 🚀/🎸 (`parse_utf8_multibyte_idents`) ficam literais no fonte, como no Rust. Conferido byte a byte contra o `.rs` (`C3 84`; `F0 9F 9A 80`, `F0 9F 8E B8`). O `Find-SuspiciousChars.ps1 -Path tests` lista as 4 linhas com U+00C4 em `SqlParserDatabricksTests.cs` (53, 54, 59, 62): são intencionais. As outras 3 linhas listadas (`Tokenizer/TokenizerTests.cs`) são preexistentes.
12. **`println!("{}", x)`** (`from_cte`, `filter_as_alias`) → `Console.WriteLine(x)`; mantém a chamada ao `Display`.
13. **Comentários `//` do Rust** mantidos em inglês na mesma posição; doc comments `///` → XML doc (`<summary>`), como em `muldiv_have_higher_precedence_than_strconcat`.

Nenhum nome novo para `nomes.md`: todos os nomes usados já são mecânicos ou já estavam registrados (`ParserError.ParserErrorValue`, `Subscript.Index(IndexValue)`, `CreateTable.CloneValue`, `Expr.MakeValue`).
