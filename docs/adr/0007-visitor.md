# ADR-0007: Visitor (`ast/visitor.rs` e o derive `Visit`/`VisitMut`) gerado por código

- **Status:** Aceita
- **Data:** 2026-10-14

## Contexto

- No Rust, o visitor tem duas partes:
  - `src/ast/visitor.rs`, escrito à mão: os traits `Visit`, `VisitMut`, `Visitor` e `VisitorMut`, os `impl` para `Option`/`Vec`/`Box`/primitivos e as funções `visit_relations`, `visit_expressions`, `visit_statements` (e as versões `_mut`);
  - o derive `#[cfg_attr(feature = "visitor", derive(Visit, VisitMut))]` (`derive/src/visit.rs`), aplicado a **530 tipos** da AST. Ele gera a travessia: chama `pre_<hook>`, visita **todos os campos na ordem da declaração** e chama `post_<hook>`. O hook vem de `#[visit(with = "visit_x")]` no tipo (9 tipos: `Expr`, `Statement`, `Query`, `Select`, `TableFactor`, `OrderBy`, `OrderByExpr`, `GroupByExpr`, `ValueWithSpan`) ou no campo (21 campos `visit_relation`). O derive só reconhece `with`; não existe `visit(skip)` na v0.63.0.
  - Um único `impl Visit` manual: `Ident` (`pre/post_visit_ident`, sem visitar o `span`).
- O derive marca cada `fn visit` com `#[cfg_attr(feature = "recursive-protection", recursive::recursive)]` (feature padrão): a pilha cresce sob demanda.
- A AST C# é feita de records imutáveis (ADR-0002, convencoes.md §6–§7). O `VisitMut` do Rust altera os nós no lugar (`&mut`).
- Tentativas conhecidas:
  - o SqlParser-cs usa um visitor por **reflexão em tempo de execução**, que quebrou no .NET Framework e é lento;
  - escrever ~530 implementações à mão seria caro e sairia do Rust a cada versão nova.

## Decisão

1. **O derive vira um gerador de código** (`tools/codegen/Generate-Visitor.ps1` + o console `tools/codegen/VisitorGen`, `net10.0`, fora da solução). Ele:
   - compila o `LeptonTech.SqlParser.Core` **sem** o código gerado (`-p:SqlParserVisitorCodegen=true`, que remove `Ast/Visitor/Generated/**`), numa pasta temporária, para funcionar mesmo com o código gerado desatualizado;
   - lê a AST por **reflexão em tempo de geração**: ordem dos campos = parâmetros do `Deconstruct` sintetizado (= construtor primário, caso 36); builders sem construtor primário usam as propriedades na ordem dos metadados; ganchos = `[VisitWith]` (caso 32);
   - **confere tudo contra o Rust** (`upstream/sqlparser-rs`): os tipos com `derive(Visit)` e os `impl Visit` manuais, nomes **e ordem** dos campos de cada struct/variante, e as anotações `visit(with)`. Qualquer diferença aborta a geração;
   - escreve um `partial` por tipo em `src/LeptonTech.SqlParser.Core/Ast/Visitor/Generated/<Pasta>.g.cs` (um arquivo por pasta da AST), com cabeçalho ASF, `<auto-generated>` e o comando de regeneração. `-Check` só verifica se os arquivos estão atualizados.
   - **Sem reflexão na biblioteca distribuída**: o código gerado é C# comum, compilado no `netstandard2.0`.
   - Alternativa rejeitada: gerador Roslyn incremental. Exigiria o pacote `Microsoft.CodeAnalysis` no build do Core, o código ficaria invisível no repositório e o diff com o upstream seria mais difícil de revisar. O padrão do projeto já é gerar e versionar (`Keywords.g.cs`).
2. **Forma C# dos traits** (convencoes.md §13, casos 125–134):
   - `trait Visit` → `interface IVisit { ControlFlow<TBreak> Visit<TBreak>(Visitor<TBreak> visitor); }` (prefixo `I`, como `ISpanned`);
   - `trait VisitMut` → `interface IVisitMut<TSelf> { ControlFlow<TBreak> Visit<TBreak>(VisitorMut<TBreak> visitor, out TSelf self); }`: o `&mut self` vira o nó devolvido (`var flow = s.Visit(mutador, out s);`);
   - `trait Visitor`/`VisitorMut` (com `type Break`) → classes abstratas `Visitor<TBreak>`/`VisitorMut<TBreak>` com ganchos `virtual` que devolvem `Continue`; nos de `VisitorMut`, o `&mut T` vira `ref T`;
   - `core::ops::ControlFlow<B>` → `Support/ControlFlow.cs`; o `()` do Rust → `ValueTuple`;
   - funções livres → classe estática `Visitor` (convive com `Visitor<TBreak>`, como `Sequence`/`Sequence<T>`).
3. **`VisitMut` sobre AST imutável:** o gancho troca o nó (`ref`); a travessia compara por **identidade** (mesma instância; mesma memória para `Sequence<T>`) e reconstrói só os pais do que mudou, com `with`. Sem mudanças, a visita devolve a mesma instância. As mudanças feitas antes de um `Break` ficam no resultado, como no Rust.
4. **Poda:** o gerador só visita campos cujo tipo alcança algum gancho (ponto fixo sobre o grafo de tipos). Campos sem ganchos alcançáveis (tokens, spans, `bool`, enums sem dados...) não têm efeito observável no Rust e ficam como comentário no código gerado. Os tipos sem nenhum gancho alcançável ainda implementam as interfaces (paridade de API), com corpo vazio.
5. **`recursive::recursive`:** cada `Visit`/`VisitMut` gerado testa `RuntimeHelpers.EnsureSufficientExecutionStack()` na entrada (`StackGuard.IsStackLow`); se faltar pilha, o resto da visita continua numa thread nova de 2 MiB (`StackGuard.Grow`; o tamanho dos segmentos do crate `recursive`) e o resultado volta para a thread original (DIV-009). `Support/StackGuard.cs` tem a mesma API que a unidade D1 usa no parser e no `Display`.
6. **Enums:** o despachante testa só o tipo da variante e chama um método estático por variante (`VisitVariant`/`VisitMutVariant`), para que cada nível de recursão use pouca pilha também no build `Debug`.
7. **Pré-requisitos para os tipos da AST:** todo tipo com `derive(Visit)` é declarado `partial` (o gerador verifica e lista os que faltam). Um `impl Visit` manual é escrito à mão no arquivo do tipo (`IVisit`, `IVisitMut<T>` e `internal static VisitMut(ref T, ..)`); o gerador o detecta e não gera esse tipo.

## Consequências

- **Fidelidade verificável:** a ordem de visita é a do Rust por construção e é conferida a cada geração. Os 7 testes de `visitor.rs` passam sem alteração; os testes próprios conferem a ordem numa consulta com CTE, junção, subconsulta e função.
- **Manutenção:** quando o upstream mudar a AST, rode `pwsh tools/codegen/Generate-Visitor.ps1` (e `-Check` em revisão/CI). O gerador acusa campos fora de ordem, renomeados ou com `visit(with)` diferente.
- **Tamanho:** cerca de 66 mil linhas geradas (2,5 MB de fonte) para ~510 tipos; a DLL `Debug` cresce cerca de 850 KB.
- **Limites conhecidos:** enums sem dados que viraram `enum` C# não implementam `IVisit` (DIV-008); em ASTs muito profundas os ganchos podem rodar em outra thread (DIV-009).
